## Критерии приёмки

- [x] DTO содержит только public order reference, безопасные timestamps, category и allowed actions.
- [x] Email, DB UUID, merchant/provider reference, tokens и raw errors отсутствуют.
- [x] DTO доступен только авторизованному verified scope.
- [x] Pending/unknown/PWA thresholds имеют однозначную семантику.
- [x] Negative serialization tests запрещают чувствительные поля.

## Evidence

- `src/lib/commercial/status-dto.ts` задаёт strict Zod DTO только из
  `orderReference`, category, allowlisted timestamps/cooldown и actions.
- Status/refresh routes остаются за hashed HttpOnly Order token; serializer не
  принимает authority из public reference и не возвращает raw destination.
- Удалены status `nextUrl` и другие legacy-поля, которые могли переносить
  internal Attempt UUID; клиент использует только allowlisted action и
  отдельный authenticated claim route.
- Pending/unknown support threshold: 5 минут от persisted payment/order
  `updatedAt`; paid_without_access: 60 секунд от authoritative `paidAt`;
  manual refresh policy: 10 секунд. Durable enforcement остаётся B3-02.
- Unknown/pending/PWA не получают `retry_payment`; terminal получает только
  `retry_payment/contact_support`; paid получает `continue_access`.
- Negative serializer regression проверяет отсутствие email, DB/payment IDs,
  merchant/provider refs/payload, token/hash, raw URL и technical error.
- DTO/unknown route regression: 12 PASS; полный `pnpm test`: 416 PASS,
  139 DB-gated skipped; `pnpm typecheck`, `pnpm lint`, `git diff --check` PASS.
- Schema/migration/business transaction не менялись; DB/concurrency coverage
  повторяется consolidated B2 reviewer.
- Отдельный review B2-06 не запускается; verdict входит в единый consolidated
  B2 milestone report после B2-07.
