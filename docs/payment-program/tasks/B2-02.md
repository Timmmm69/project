## Цель

Представлять неподтверждённый provider/status transport outcome как transient API projection без ложного terminal state.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [x] `payment_status_unknown` не означает paid/failed и не меняет подтверждённый business state.
- [x] Новый DB enum не добавлен без отдельного доказанного требования.
- [x] Status/refresh DTO типизированы и не раскрывают provider details.
- [x] Unknown запрещает повторную оплату.
- [x] Есть unit/integration tests для timeout, malformed и unavailable status.

## Обязательные проверки

- [x] `pnpm lint`.
- [x] `pnpm typecheck`.
- [x] `pnpm test` плюс targeted unit/integration tests.
- [x] Релевантный migration/transaction/concurrency smoke.

## Evidence

- `commercialOrderStatus` принимает только transient
  `payment_status_unknown` projection и сохраняет persisted Order/Attempt state;
  Prisma schema/migrations не менялись.
- Manual refresh проецирует unknown только для active pending aggregate при
  timeout/unavailable provider, неподтверждённом response или rejected
  authoritative decision; в этих ветках payment processor не вызывается.
- Unknown DTO содержит прежние безопасные поля, возвращает
  `WAIT_FOR_PAYMENT`, не содержит provider/merchant/internal identifiers и не
  предлагает retry/Access.
- Provider status input получил ожидаемые server-owned amount/currency без
  изменения merchant-blocked WEBPAY activation.
- Новый route-level regression: 6 PASS для timeout, malformed, reference
  ambiguity, provider unavailable, authoritative pending и rejected outcome.
- Полный `pnpm test`: 410 PASS, 139 DB-gated skipped; `pnpm typecheck` PASS;
  `pnpm lint` PASS; `git diff --check` PASS.
- DB migration не требуется; existing commercial concurrency regression
  остаётся частью consolidated B2 review.
- Отдельный review B2-02 не запускается: карточка принимается единым
  consolidated B2 milestone report после B2-07.
