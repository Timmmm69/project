## Цель

Принимать commercial mutations только из допустимого first-party origin/host с корректной proxy boundary.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

Audit/traceability IDs: `SEC-01`, `SEC-02`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [x] Отсутствующий/чужой Origin на browser mutation отклоняется по утверждённой политике.
- [x] Host/proto проверяются с учётом только trusted proxy configuration.
- [x] Server-to-server callback имеет отдельную auth/signature boundary.
- [x] Cross-origin, host spoofing и missing-origin tests покрыты.
- [x] Generic/internal clients не ломаются без явной совместимой политики.

## Обязательные проверки

- [x] `pnpm lint`.
- [x] `pnpm typecheck`.
- [x] `pnpm test` плюс targeted unit/integration tests.
- [x] Релевантный migration/transaction/concurrency smoke.

## Evidence

- `src/lib/commercial/origin-policy.ts`: единый trusted-origin helper с единой точкой политики (не копирование по routes).
- `requireTrustedOrigin(request)`: отклоняет missing Origin (strict), foreign Origin, mismatched Host.
- Host/proto проверяются только при `TRUSTED_PROXY=true` (explicit policy).
- `x-forwarded-host` и `x-forwarded-proto` не доверяются без explicit flag.
- Server-to-server callback boundary сохранён: `POST /api/payments/webpay/notify` и `POST /api/commercial/fake-checkout` не используют browser-origin check.
- Применено ко всем 6 commercial mutation routes:
  - `POST /api/commercial/orders`
  - `POST /api/commercial/orders/[publicId]/payment-session`
  - `POST /api/commercial/orders/[publicId]/refresh-status`
  - `POST /api/commercial/orders/[publicId]/claim-access`
  - `POST /api/commercial/orders/[publicId]/start-attempt`
  - `POST /api/commercial/checkout-flows`
- Test/internal client policy: `x-test-internal-request` header в development/test (неявный bypass запрещён).
- `tests/unit/commercial-origin-policy.test.ts`: 24/24 PASS — foreign origin, missing origin, host spoofing, trusted proxy, untrusted forwarded headers, callback boundary, test-internal policy.
- `pnpm typecheck`, `pnpm lint`, `pnpm test` (441 PASS, 140 DB-gated skipped) — PASS.
- Обновлены существующие тесты для совместимости с новой strict-политикой.
- Production остаётся `NO-GO`; чужие файлы не тронуты.
