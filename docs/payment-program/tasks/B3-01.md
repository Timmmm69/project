## Цель

Принимать commercial mutations только из допустимого first-party origin/host с корректной proxy boundary.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

Audit/traceability IDs: `SEC-01`, `SEC-02`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [ ] Отсутствующий/чужой Origin на browser mutation отклоняется по утверждённой политике.
- [ ] Host/proto проверяются с учётом только trusted proxy configuration.
- [ ] Server-to-server callback имеет отдельную auth/signature boundary.
- [ ] Cross-origin, host spoofing и missing-origin tests покрыты.
- [ ] Generic/internal clients не ломаются без явной совместимой политики.

## Обязательные проверки

- [ ] `pnpm lint`.
- [ ] `pnpm typecheck`.
- [ ] `pnpm test` плюс targeted unit/integration tests.
- [ ] Релевантный migration/transaction/concurrency smoke.

## Evidence

- Ссылки на изменённые файлы/коммиты.
- Вывод обязательных проверок.
- Runtime/design/external evidence согласно карточке.
- Отдельный `reviews/B3-01.md` перед `DONE`.

## Handoff

Следующее точное действие: После revalidation оформить threat-model decision и обновить route helpers/tests.

Нерешённые вопросы должны быть перечислены здесь и в `docs/payment-program/handoff.md`; молчаливые архитектурные, финансовые, security или scope решения запрещены.
