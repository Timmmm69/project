## Критерии приёмки

- [x] `POST /api/commercial/orders` не доверяет email из request body.
- [x] До verification нельзя узнать Existing Order/Access/Result.
- [x] После verification используется normalized email из authority.
- [x] Same-flow replay и concurrent submit не создают второй Order.
- [x] Unauthorized/expired/cross-scope session получает безопасный отказ.

## Evidence

- Canonical `POST /api/commercial/orders` использует отдельную strict schema без
  `email`; client-supplied email отклоняется как invalid command.
- Route fail-closed требует `acc01a_recovery` authority и доступный recovery
  runtime; off/shadow/missing-cookie пути завершаются до вызова Order service.
- `createCommercialOrder` получает opaque authority, извлекает normalized email
  только через server-side `validateRecoverySession` и повторяет проверку внутри
  Order transaction до чтения checkout Order/Access/Attempt state.
- Concurrent unique-conflict recovery также повторно валидирует authority в
  отдельной transaction до same-flow/open-order queries.
- Verified path сохраняет `emailOriginal` и `emailNormalized` из authority,
  игнорируя spoofed email даже в прямом service command; server price/currency,
  legal checks, checkout-flow/idempotency constraints не ослаблены.
- HTTP unit boundary: 4/4 PASS — missing cookie, strict no-email command,
  client email rejection и off-mode fail-closed. Связанные targeted unit tests:
  3 files, 25/25 PASS.
- Fresh 14-migration dedicated schema; extended recovery/Order integration:
  24/24 PASS, включая spoofed email, missing/invalid/expired/cross-product
  authority, same-flow concurrent submit и exactly-one Order. Schema удалена.
- Финальный lint — PASS; typecheck — PASS; полный regression run: 26 files,
  399 tests PASS, 139 database-gated tests ожидаемо skipped.
- Новая DB migration не потребовалась; production не активирована и остаётся
  `NO-GO`. Checkout UI для получения verified email authority относится к C-01.
- Отдельный `reviews/B1-04.md` требуется перед `DONE` как один Tier-1 review
  всего milestone; внутренние подшаги отдельно не ревьюятся.
