## Критерии приёмки

- [x] Retry разрешён только из failed/cancelled/expired.
- [x] Создаётся новая PaymentAttempt в существующем Order.
- [x] Pending/unknown/PWA не допускают retry.
- [x] Transition table, service и tests описывают одинаковую семантику.

## Evidence

- `src/lib/commercial/state-machine.ts`: initial attempt разрешён только для
  `CREATED`, terminal retry — только для `FAILED/CANCELLED/EXPIRED`;
  `PENDING` и `PAID` не проходят retry contract. Transient unknown сохраняет
  persisted `PENDING`, а PWA — persisted `PAID`, поэтому также не открывают retry.
- `src/lib/commercial/commercial-service.ts`: Order блокируется `FOR UPDATE`;
  terminal retry проверяет совпадение последней terminal PaymentAttempt со
  статусом Order и создаёт новую PaymentAttempt в том же Order. Partial unique
  DB index продолжает обеспечивать не более одной active attempt.
- Browser/provider return URL остаётся только навигационным сигналом и не
  участвует в state transition; оплату подтверждает только authoritative
  provider processing path.
- `tests/unit/commercial-security.test.ts`: 21/21 targeted unit PASS, включая
  отрицательные `PENDING/PAID` и положительные terminal states.
- `tests/e2e/commercial-concurrency.spec.ts`: 16/16 PostgreSQL PASS, включая
  dedicated failed/cancelled/expired retry и восемь параллельных retry с ровно
  одной active PaymentAttempt.
- `pnpm test`: 417 PASS, 139 DB-gated skipped; `pnpm typecheck` и `pnpm lint`:
  PASS; `prisma migrate status`: 15 migrations, schema up to date.
- Миграция не добавлялась: invariant одной active PaymentAttempt уже защищён
  существующим partial unique index.
- Production остаётся `NO-GO`; WEBPAY assumptions и merchant gates не закрыты.
- Вместо отдельного `reviews/B2-05.md` карточка ожидает требуемый пользователем
  consolidated B2 payment-state milestone review.
