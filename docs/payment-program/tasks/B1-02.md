## Цель

Реализовать OTP recovery domain, API и fake mailer строго в dev/test с production fail-closed.

## Источники требований

- `acc-01a-recovery-spec-v1.md`
- `acc-01a-session-bridge-decision-v1.md`

Audit/traceability IDs: `REC-03`, `SEC-01`, `SEC-02`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [x] Challenge/attempt/session lifecycle и one-time OTP соответствуют ACC-01A.
- [x] Существующий и несуществующий email имеют совместимый публичный ответ.
- [x] Raw OTP не хранится и не логируется; fake mailbox изолирован от production build.
- [x] Feature flag default-off, production-like activation fail-closed.
- [x] Concurrent verify/replay/resend не создают вторую active session.

## Обязательные проверки

- [x] `pnpm lint`.
- [x] `pnpm typecheck`.
- [x] `pnpm test` плюс targeted unit/integration tests.
- [x] Релевантный migration/transaction/concurrency smoke.

## Evidence

- Перенесены два ранее reviewed sibling milestones без merge ветки:
  recovery domain `ad7af7a` и HTTP boundary `03f01c7`; hash-check подтверждает
  exact equality всех 19 новых source/test/migration files с `03f01c7`.
- Additive migration `20260713220000_add_acc01a_recovery_domain_foundation`
  создаёт challenge, verification attempt, recovery session, durable limiter и
  restricted security-event tables/enums/indexes без backfill бизнес-таблиц.
- Domain config default-off; enable разрешён только в dev/test, а
  production-like activation запрещена независимо от flag.
- Четыре отдельные versioned HMAC key rings используются для email fingerprint,
  challenge token, OTP MAC и recovery session token; reuse других app secrets
  отклоняется.
- OTP: 6 CSPRNG digits, 10-minute TTL, challenge-bound MAC, maximum five failed
  attempts, terminal replay semantics и raw value только в process memory.
- Recovery session: 30-minute absolute TTL, HttpOnly/SameSite=Strict cookie,
  revocation/invalidation и no sliding extension.
- Durable PostgreSQL rate-limit events покрывают email/source request и failed
  verify limits без raw email/IP persistence.
- Fake/test mailer не имеет network/production fallback; runtime создаёт его
  только при валидной dev/test config. Inspection hook существует только как
  injected test harness capability; inspection API route не добавлен.
- Public HTTP boundary требует JSON, exact schemas, UUID idempotency, trusted
  Origin/Host и recovery intent; disabled/production-like config отвечает 404
  до parsing/database writes.
- Request/verify/session responses используют allowlist DTO и neutral timing;
  User/Order/Payment/Access/Attempt/Result existence не раскрывается.
- Recovery domain не создаёт и не изменяет User, Order, PaymentAttempt, Access,
  Attempt, Answer, Result или VerifiedStudentSession.
- CI запускает verified-session, recovery-domain и recovery-HTTP database suites
  последовательно на dedicated `acc01a_recovery_ci` schema.

- Lint — PASS; typecheck — PASS.
