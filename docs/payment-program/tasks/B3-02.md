## Цель

Заменить process-memory limiter на устойчивый механизм с trusted client identity и понятным cooldown contract.

## Критерии приёмки

- [x] Limits переживают несколько instances/restart в выбранной deployment architecture.
- [x] Raw untrusted `x-forwarded-for` не является authority.
- [x] Ответ содержит безопасный `Retry-After`/cooldown.
- [x] Email recovery, order, status refresh и brute-force limits разнесены.
- [x] Shared-network и concurrency scenarios проверены.
