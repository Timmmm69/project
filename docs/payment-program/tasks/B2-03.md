## Evidence

- `reconcilePaidCommercialOrderAccess` принимает только persisted `PAID` Order
  с ровно одной consistent PAID PaymentAttempt, row-locks Order и создаёт Access
  из immutable Order snapshot в одной transaction.
- Shared `ensurePaidOrderAccess` используется и обычным authoritative paid
  transition, и reconciliation; unique `Access.commercialOrderId` плюс row lock
  обеспечивают exactly-one Access.
- Authoritative paid replay автоматически разрешает PWA; browser return/status
  category сама не создаёт Access и не является payment proof.
- Safe DTO показывает `paid_without_access`, только refresh и public reference;
  через 60 секунд allowlist добавляет support. Retry/payment/refund actions нет.
- Operational detection/resolution пишутся внутри domain transaction; canonical
  `paid_without_access_detected/resolved` analytics пишутся только после commit,
  idempotent transition keys, keyed opaque hashes, без PII/provider data.
- PostgreSQL Playwright concurrency: 12/12 PASS, включая 8 параллельных
  reconciler calls → 1 `resolved`, 7 `already_resolved`, ровно 1 Access,
  1 detected + 1 resolved event, 0 новых PaymentAttempt и 0 refund events.
- Full `pnpm test`: 417 PASS, 139 DB-gated skipped; `pnpm typecheck`, `pnpm lint`,
  `git diff --check` PASS.
- Prisma schema/migration не менялись; production/provider gates остаются
  `NO-GO/BLOCKED_EXTERNAL`.
- Отдельный review B2-03 не запускается; verdict входит в единый consolidated
  B2 milestone report после B2-07.
