## Цель

Восстанавливать текущий payment context после reload, Back, bfcache, focus и mobile foreground.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

Audit/traceability IDs: `REC-01`, `REC-02`, `REC-03`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [ ] Reload до и после provider return не создаёт новые entities.
- [ ] `pageshow`, `visibilitychange` и focus обновляют только разрешённый status.
- [ ] Back/mobile app switch восстанавливают текущий verified state.
- [ ] Повторный вход использует resolver и не раскрывает существование records до verification.
- [ ] Context loss приводит к recovery/support, а не новой оплате.

## Обязательные проверки

- [ ] `pnpm lint`.
- [ ] `pnpm typecheck`.
- [ ] `pnpm test`.
- [ ] Релевантные Playwright/browser scenarios и ручная visual check.
