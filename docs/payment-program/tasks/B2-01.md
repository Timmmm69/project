## Критерии приёмки

- [x] Snapshot включает попытки, start window, timer, retention, exam/display mode и legal version.
- [x] Старые Order/Access читаются после совместимой миграции.
- [x] Редактирование Product после покупки не меняет купленные условия.
- [x] Access создаётся из snapshot внутри существующей payment transaction.
- [x] Цена/валюта остаются server-defined.

## Обязательные проверки

- [x] `pnpm lint`.

- [x] `pnpm test` плюс targeted unit/integration tests.
- [x] Релевантный migration/transaction/concurrency smoke.

  `20260801223000_add_immutable_commercial_order_snapshot` добавляют
  attempts/start-window/duration/retention/exam/display snapshot с двухфазным
  nullable → backfill → `NOT NULL` переходом и DB constraints.
- `src/lib/commercial/commercial-service.ts` валидирует server-owned условия,
  фиксирует их при создании Order и создаёт Access только из Order snapshot
  внутри существующей payment transaction.
- `src/server/recovery/state-resolver.ts` использует Order snapshot для
  existing entitlement и Result retention, не mutable Product terms.
- Unit resolver: 56/56 PASS, включая изменённый Product и fail-closed
  inconsistent purchased snapshot.

  15-я миграция → все шесть новых полей backfilled корректно; temporary
  `b201_ci` schema удалена и подтверждена отсутствующей.

  Test между Order и paid callback, а Access сохраняет 1 attempt и 90-day
