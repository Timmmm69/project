## Цель

Сохранять все купленные коммерческие условия и использовать snapshot, а не mutable Product, при Access grant.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [ ] Snapshot включает попытки, start window, timer, retention, exam/display mode и legal version.
- [ ] Старые Order/Access читаются после совместимой миграции.
- [ ] Редактирование Product после покупки не меняет купленные условия.
- [ ] Access создаётся из snapshot внутри существующей payment transaction.
- [ ] Цена/валюта остаются server-defined.
