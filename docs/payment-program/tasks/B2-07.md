## Цель

Позволить verified recovery безопасно продолжить current Order/payment без создания финансовых сущностей.

## Критерии приёмки

- [x] Pending/active payment не преобразуется в `no_access`.
- [x] Resolver read-only относительно Order/Attempt/Payment/Access.
- [x] Continuation восстанавливает authority/context, но не инициирует оплату автоматически.
- [x] Unknown/PWA направляются в безопасные состояния.
- [x] Repeated/concurrent resolver calls не создают business records.

## Evidence

- `src/server/recovery/state-resolver.ts`: verified resolver добавляет только
  закрытые outcomes `payment_pending` и `paid_without_access`, без public/internal
  entity IDs. Разрешённое действие — `VIEW_PAYMENT_STATUS`; оно не проходит
  ACC-01A `CONTINUE` exchange и не расширяет PRE/ATT/RES destination guards.
- Pending state требует согласованного immutable Order snapshot и ровно одной
  active PaymentAttempt (либо CREATED Order до первой попытки); paid-without-access
  требует ровно одну PAID attempt и отсутствие active attempt. Ambiguous truth
  остаётся `support_required`.
- `src/app/api/commercial/orders/[publicId]/refresh-status/route.ts` вызывает
  authoritative processor с `grantAccess: false`: manual refresh не создаёт
  Order, PaymentAttempt или Access. Provider/browser return сам оплату не доказывает.
- Transient unknown остаётся projection persisted PENDING и восстанавливается как
  safe payment context; committed PAID без Access восстанавливается как
  `paid_without_access`. Ни одно состояние не инициирует оплату автоматически.
- Targeted unit decision/continuation/status suites: 107/107 PASS; strict recovery
  response по-прежнему имеет ровно три ключа и не содержит идентификаторов/PII.
- Fresh isolated `acc01a_recovery_ci`: 15/15 migrations applied; recovery resolver
  integration 20/20 PASS, включая восемь concurrent pending reads без business
  writes; тестовая schema после проверки удалена.
- Commercial PostgreSQL concurrency 17/17 PASS: authoritative manual status
  меняет только подтверждённый status/event truth и создаёт 0 новых
  Order/PaymentAttempt/Access; resulting state — `paid_without_access`.
- `pnpm test`: 417 PASS, 140 DB-gated skipped; `pnpm lint`, `pnpm typecheck`:
  PASS; public `prisma migrate status`: 15 migrations, schema up to date.
- Production остаётся `NO-GO`; merchant dependencies не закрывались mock/sandbox
  evidence. Автоматический refund отсутствует.
- Вместо отдельного `reviews/B2-07.md` карточка ожидает требуемый consolidated
  B2 payment-state milestone review.
