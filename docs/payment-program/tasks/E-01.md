## Цель

Получить authoritative merchant eligibility, credentials и merchant-specific integration documentation.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

Audit/traceability IDs: `PAY-07`, `DOC-02`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [ ] Подтверждены seller/service eligibility и agreement.
- [ ] Получены sandbox credentials безопасным каналом; production secrets не попали в репозиторий.
- [ ] Получена актуальная merchant-specific документация с версией/датой.
- [ ] Определены владельцы provider вопросов.
- [ ] Marketing page не используется как protocol evidence.

## Обязательные проверки

- [ ] Проверка authoritative происхождения evidence.
- [ ] Проверка отсутствия secrets/PII в репозитории.
- [ ] Независимый gate review; mock/assumption не принимается как закрытие.

## Evidence

- Ссылки на изменённые файлы/коммиты.
- Вывод обязательных проверок.
- Runtime/design/external evidence согласно карточке.
- Отдельный `reviews/E-01.md` перед `DONE`.

## Handoff

Следующее точное действие: Ожидать merchant/provider материалы; после получения сохранить только безопасные метаданные/evidence.

Нерешённые вопросы должны быть перечислены здесь и в `docs/payment-program/handoff.md`; молчаливые архитектурные, финансовые, security или scope решения запрещены.
