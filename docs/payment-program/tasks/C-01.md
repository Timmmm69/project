## Цель

Реализовать checkout/email/review flow с точной коммерческой, legal и provider-handoff информацией.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/ux-state-contract-v1.md`
- `docs/00-final-mvp-spec-v2.md`

Audit/traceability IDs: `UI-01`, `ORD-03`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [x] До CTA показаны 10 BYN, одна попытка, 90 дней, 120 минут, primary-only и отсутствие подписки.
- [x] Email подтверждён до review/Order — через recovery OTP flow (B1-04), order API использует `commercialVerifiedOrderSchema` (email не из body).
- [x] Оба required checkbox не preselected и связаны с validation summary:
  - «Подтверждаю, что мне исполнилось 18 лет и указанный email находится под моим контролем.»
  - «Подтверждаю ознакомление с публичной офертой, условиями оплаты и возврата, а также политикой обработки персональных данных.»
- [x] Seller/support/offer/refund/privacy предусмотрены — ссылки на offer, privacy, refund policy, disclaimer, support email.
- [x] CTA и payment method используют точный WEBPAY redirect copy — «Перейти к оплате картой», «Вы будете перенаправлены на защищённую страницу WEBPAY», «Номер карты, срок действия, CVV/CVC и данные 3-D Secure вводятся только на стороне WEBPAY. Наш сайт не получает реквизиты карты.»

## Evidence

- `src/app/(public)/tests/[slug]/commercial-checkout-form.tsx` — полная переработка:
  - **Шаг 1: Email verification** — интеграция recovery API (`POST /api/recovery/challenges`, `POST /api/recovery/challenges/verify`), OTP-инпут с маскированным email, кнопки «Подтвердить email» / «Изменить email».
  - **Шаг 2: Checkout review** — иерархия: price/one-attempt (Level 1) → constraints 90д/120мин/primary-only (Level 2) → payment method с WEBPAY redirect notice (Level 3) → legal/support (Level 4).
  - **Section: «Банковская карта»** — точный copy: «Вы будете перенаправлены на защищённую страницу WEBPAY.»
  - **Section: «Подтверждение условий»** — два checkbox: adult confirmation + legal acceptance, не preselected, оба обязательны для CTA.
  - **Primary CTA:** «Перейти к оплате картой», заблокирован до верификации email + оба checkbox.
  - **Redirect loader:** «Открываем защищённую страницу WEBPAY…» с spinner + fallback «Открыть страницу WEBPAY» через 10 сек.
  - **Post-payment:** восстановление заказа по `?commercialOrder=`, статусные сообщения, кнопки «Попробовать оплатить снова» / «Обновить статус» / «Перейти к началу теста».
  - **Verified pre-authorized:** сохранён flow для уже авторизованных студент-сессий.
- `src/app/(public)/tests/[slug]/page.tsx` — передаёт `productCode={COMMERCIAL_PRODUCT_CODE}` в `CommercialCheckoutForm`.
- `src/app/globals.css` — добавлены `.checkbox-row`, `.checkout-section`, `.checkout-loader`, `.spinner` с reduced-motion.
- Card fields (PAN/CVV), ЕРИП, popup/new-tab — отсутствуют.
- Backend truth не нарушается: order API использует `commercialVerifiedOrderSchema` (email из recovery cookie), browser return ≠ payment confirmation.
