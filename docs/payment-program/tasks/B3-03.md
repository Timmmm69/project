## Цель

Исключить кэширование и referrer/URL leakage на payment pages и API.

## Источники требований

- `docs/payment-program/sources/payment-ux-contract-v1.md`
- `docs/payment-program/sources/payment-core-audit-2026-07-18.md`

Audit/traceability IDs: `SEC-03`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [x] Payment HTML/API задают `Cache-Control: no-store`.
- [x] Страницы задают строгий referrer policy.
- [x] Tokens и provider references не попадают в URL.
- [x] Public order reference используется только в разрешённом контексте.
- [x] Header/redirect tests покрывают positive и negative cases.

## Обязательные проверки

- [x] `pnpm lint`.
- [x] `pnpm typecheck`.
- [x] `pnpm test` плюс targeted unit/integration tests.
- [x] Релевантный migration/transaction/concurrency smoke.

## Evidence

- `src/lib/api-response.ts` — `PAYMENT_RESPONSE_HEADERS` константа, `paymentHeaders()` helper; `apiSuccess`/`apiFailure` всегда включают `Cache-Control: no-store` + `Referrer-Policy: no-referrer`.
- `tests/unit/commercial-response-policy.test.ts` — 31 тест: positive/error headers, status codes, Retry-After merge, no cacheable headers, no header leak в body.
- 483 tests PASS, typecheck/lint clean.
- Recovery модуль уже имеет свои `RECOVERY_RESPONSE_HEADERS` в `src/server/recovery/http-response.ts`.
