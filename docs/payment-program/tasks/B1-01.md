## Цель

Реализовать отдельную opaque server-side verified commercial session без fallback на legacy `student_session`.

## Источники требований

- `acc-01a-session-bridge-decision-v1.md`

Audit/traceability IDs: `ORD-03`, `SEC-01`, `REC-03`.

## В scope

- Реализовать только цель и критерии этой карточки.
- Сохранить backend truth, idempotency, transaction и privacy invariants.
- Обновить board, evidence и handoff вместе с изменением.

## Вне scope

- Реализация соседних карточек без отдельного claim.
- Production activation или изменение gate verdict.
- Card-data UI, embedded bank form, автоматические возвраты и другие запрещённые MVP-функции.


## Критерии приёмки

- [ ] Session scope привязан к точным User/Product/Test/Access.
- [ ] Разрешены только issuers `EMAIL_OTP_RECOVERY`, `ACCESS_CODE`, `COMMERCIAL_ORDER_CLAIM`.
- [ ] `/api/students/identify` не может выдать verified commercial authority.
- [ ] Cookie/token lifecycle, hashing, rotation, revocation и concurrency соответствуют bridge decision.
- [ ] Generic MVP продолжает использовать legacy plane без смешивания.
