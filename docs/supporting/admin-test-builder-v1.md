# **Admin Test Builder v1**

## **1\. Назначение документа**

Документ описывает админский конструктор тестов для MVP v1.1.

Admin Test Builder нужен, чтобы преподаватель мог без разработчика:

1. создать тест;  
2. настроить тест;  
3. добавить вопросы вручную;  
4. загрузить вопросы через Excel/CSV;  
5. отредактировать вопросы после импорта;  
6. настроить режим оценивания;  
7. настроить доступы;  
8. проверить тест через предпросмотр;  
9. опубликовать тест;  
10. смотреть базовую готовность теста к продаже.

Документ описывает только административную часть создания и настройки тестов. Оплата, доступы, коды и API подробно описываются в отдельных документах, но здесь учитываются их точки входа в интерфейсе теста.

---

## **2\. Главная цель Admin Test Builder**

Цель конструктора:

Преподаватель должен иметь возможность самостоятельно создать полноценный тест по русскому языку для ЦЭ/ЦТ или тренировочной подготовки без участия разработчика.

Конструктор должен поддерживать два способа работы:

1. создание теста вручную;  
2. импорт вопросов через Excel/CSV.

После любого способа создания преподаватель должен иметь возможность вручную редактировать тест и вопросы.

---

## **3\. Основные принципы**

1. Конструктор должен быть понятен преподавателю, а не только разработчику.  
2. Ручное создание вопросов входит в MVP и не является второстепенной функцией.  
3. Импорт Excel/CSV входит в MVP и должен быть не технической загрузкой файла, а понятным сценарием с проверкой ошибок.  
4. Все вопросы после импорта должны редактироваться вручную.  
5. Перед публикацией система должна проверить тест и показать ошибки.  
6. Тест нельзя опубликовать, если он технически невалиден.  
7. Предпросмотр теста входит в MVP.  
8. Старые результаты учеников не должны ломаться после редактирования теста.  
9. Объяснения к вопросам необязательны в первой версии.  
10. Темы обязательны, потому что по ним строится результат.

---

## **4\. Раздел “Тесты”**

В админке должен быть раздел:

**Тесты**

Это основной раздел, откуда преподаватель управляет всеми тестами.

---

## **5\. Список тестов**

### **5.1. Что показывает таблица тестов**

Таблица тестов должна показывать:

1. название теста;  
2. предмет;  
3. режим теста;  
4. статус;  
5. количество вопросов;  
6. максимальный балл;  
7. цену;  
8. количество продаж;  
9. количество прохождений;  
10. дату последнего обновления;  
11. действия.

### **5.2. Статусы теста**

Тест может иметь статусы:

1. **Черновик**;  
2. **Опубликован**;  
3. **Скрыт**;  
4. **Архив**, можно заложить на будущее.

### **5.3. Значение статусов**

**Черновик**  
 Тест не виден ученикам. Его можно редактировать.

**Опубликован**  
 Тест виден в каталоге. Его можно купить или активировать по коду.

**Скрыт**  
 Тест не виден в каталоге и недоступен для новых покупок, но старые результаты сохраняются.

**Архив**  
 Можно заложить на будущее для старых тестов.

---

## **6\. Действия в списке тестов**

Для каждого теста нужны действия:

1. открыть;  
2. редактировать;  
3. перейти к вопросам;  
4. предпросмотр;  
5. опубликовать;  
6. скрыть;  
7. удалить, если безопасно;  
8. посмотреть результаты;  
9. посмотреть оплаты;  
10. создать код доступа, можно как быстрый переход.

### **6.1. Удаление теста**

Физически удалять тест не рекомендуется.

Если у теста есть:

1. оплаты;  
2. доступы;  
3. попытки;  
4. результаты,

то тест нельзя физически удалить. Можно только скрыть или архивировать.

---

## **7\. Кнопка создания теста**

В разделе “Тесты” должна быть основная кнопка:

**Создать тест**

После нажатия открывается форма создания теста.

---

## **8\. Создание теста**

### **8.1. Поля формы создания теста**

Форма создания теста должна содержать:

1. название теста;  
2. предмет;  
3. режим теста;  
4. краткое описание;  
5. полное описание;  
6. цена;  
7. валюта;  
8. время прохождения;  
9. количество попыток;  
10. срок доступа после покупки;  
11. статус.

---

## **9\. Поля теста**

### **9.1. Название теста**

Поле:

**Название теста**

Пример:

**Русский язык. Тренировочный тест №1**

Обязательно.

---

### **9.2. Предмет**

Поле:

**Предмет**

В MVP доступно значение:

1. русский язык.

Техническое значение:

`russian`

Поле нужно оставить как отдельную настройку, чтобы в будущем добавить другие предметы.

---

### **9.3. Режим теста**

Поле:

**Режим теста**

Варианты:

1. тренировочный;  
2. ЦЭ/ЦТ.

Технические значения:

1. `training`;  
2. `ce_ct`.

### **Тренировочный режим**

Используется для обычных тренировочных тестов.

Результат:

1. первичный балл;  
2. процент;  
3. уровень;  
4. темы;  
5. ошибки;  
6. правильные ответы.

### **Режим ЦЭ/ЦТ**

Используется для тестов, приближенных к формату ЦЭ/ЦТ.

Результат:

1. первичный балл;  
2. тестовый балл 0-100, если подключена шкала;  
3. темы;  
4. ошибки;  
5. правильные ответы.

Важно: в интерфейсе результата нельзя писать, что это официальный результат экзамена. Нужно писать:

**Тренировочный расчёт по таблице соответствия первичных и тестовых баллов.**

---

### **9.4. Краткое описание**

Поле:

**Краткое описание**

Используется в карточке теста в каталоге.

Пример:

**Тренировочный тест по русскому языку для подготовки к ЦЭ/ЦТ.**

Желательно, но можно не блокировать сохранение черновика.

---

### **9.5. Полное описание**

Поле:

**Полное описание**

Используется на странице теста.

Можно указать:

1. что проверяет тест;  
2. кому подходит;  
3. что ученик увидит после прохождения;  
4. сколько времени займёт тест;  
5. какие правила прохождения.

Необязательно для черновика, желательно перед публикацией.

---

### **9.6. Цена**

Поле:

**Цена**

Обязательно перед публикацией.

Хранить в минимальных единицах валюты.

Пример:

1. 15 BYN \= 1500 копеек;  
2. 20 BYN \= 2000 копеек.

---

### **9.7. Валюта**

Поле:

**Валюта**

Предварительно:

`BYN`

Финально зависит от платёжного провайдера.

---

### **9.8. Время прохождения**

Поле:

**Время прохождения**

Единица:

минуты.

Пример:

1. 45 минут;  
2. 60 минут;  
3. 90 минут.

Обязательно перед публикацией.

---

### **9.9. Количество попыток**

Поле:

**Количество попыток после покупки**

Для первой версии значение по умолчанию:

1 попытка.

Поле всё равно должно быть настраиваемым, чтобы в будущем можно было давать 2-3 попытки.

---

### **9.10. Срок доступа**

Поле:

**Срок доступа после покупки**

Рекомендованное значение по умолчанию:

7 дней.

Это значит, что после оплаты ученик может начать тест в течение 7 дней.

Если попытка уже началась, её можно завершить даже если срок доступа истёк во время прохождения.

---

### **9.11. Статус**

Новый тест по умолчанию создаётся в статусе:

**Черновик**

---

## **10\. Кнопки на форме создания теста**

На форме создания теста нужны кнопки:

1. **Сохранить черновик**;  
2. **Сохранить и перейти к вопросам**;  
3. **Отменить**.

### **10.1. Сохранить черновик**

Сохраняет тест без публикации.

Можно сохранить даже если ещё нет вопросов.

### **10.2. Сохранить и перейти к вопросам**

Сохраняет основные настройки и открывает вкладку вопросов.

### **10.3. Отменить**

Возвращает к списку тестов.

---

## **11\. Страница редактирования теста**

После создания теста открывается страница редактирования.

Страница должна иметь вкладки:

1. **Основное**;  
2. **Вопросы**;  
3. **Импорт**;  
4. **Предпросмотр**;  
5. **Настройки оценивания**;  
6. **Настройки доступа**;  
7. **Результаты**.

# **12\. Вкладка “Основное”**

На вкладке “Основное” редактируются базовые данные теста:

1. название;  
2. предмет;  
3. режим;  
4. краткое описание;  
5. полное описание;  
6. цена;  
7. валюта;  
8. время прохождения;  
9. статус.

---

## **13\. Вкладка “Вопросы”**

Вкладка “Вопросы” является главным рабочим экраном конструктора.

### **13.1. Верхний блок вкладки**

Вверху нужно показать:

1. количество вопросов;  
2. максимальный балл;  
3. количество тем;  
4. режим теста;  
5. предупреждения по готовности.

Пример:

**Вопросов: 40**  
 **Максимальный балл: 40**  
 **Тем: 7**  
 **Статус: Черновик**

---

### **13.2. Основные кнопки**

На вкладке “Вопросы” нужны кнопки:

1. **Добавить вопрос**;  
2. **Импортировать из Excel/CSV**;  
3. **Скачать шаблон**;  
4. **Предпросмотр теста**.

---

## **14\. Список вопросов**

### **14.1. Что показывает список вопросов**

Список вопросов должен показывать:

1. номер;  
2. текст вопроса;  
3. тип вопроса;  
4. правильный ответ;  
5. тема;  
6. подтема;  
7. баллы;  
8. наличие объяснения;  
9. действия.

### **14.2. Действия с вопросом**

Для каждого вопроса нужны действия:

1. редактировать;  
2. удалить;  
3. переместить вверх;  
4. переместить вниз.

### **14.3. Что можно добавить позже**

Можно вынести в P1:

1. дублировать вопрос;  
2. массовое удаление;  
3. drag-and-drop;  
4. фильтр по теме;  
5. поиск по тексту вопроса.

## **15\. Добавление вопроса**

При нажатии **Добавить вопрос** открывается форма вопроса.

Форма должна поддерживать три типа вопросов:

1. один правильный ответ;  
2. несколько правильных ответов;  
3. короткий текстовый ответ.

Технические значения:

1. `single_choice`;  
2. `multiple_choice`;  
3. `short_text`.

---

## **16\. Общие поля вопроса**

Общие поля для всех типов вопросов:

1. текст вопроса;  
2. тип вопроса;  
3. правильный ответ;  
4. тема;  
5. подтема;  
6. сложность;  
7. баллы;  
8. источник/комментарий;  
9. объяснение.

---

## **17\. Обязательные поля вопроса**

Вопрос нельзя сохранить без:

1. текста вопроса;  
2. типа вопроса;  
3. правильного ответа;  
4. темы;  
5. баллов.

---

## **18\. Необязательные поля вопроса**

В MVP необязательны:

1. подтема;  
2. сложность;  
3. источник;  
4. объяснение.

Объяснение необязательно, потому что в первой версии достаточно показывать правильный ответ после завершения теста.

---

# **19\. Тип вопроса: один правильный ответ**

## **19.1. Название в интерфейсе**

**Один правильный ответ**

## **19.2. Техническое значение**

`single_choice`

## **19.3. Поля**

Для этого типа нужны поля:

1. текст вопроса;  
2. вариант A;  
3. вариант B;  
4. вариант C;  
5. вариант D;  
6. правильный ответ;  
7. тема;  
8. подтема;  
9. баллы;  
10. объяснение, необязательно.

## **19.4. Правильный ответ**

Правильный ответ должен быть одним из значений:

1. A;  
2. B;  
3. C;  
4. D.

## **19.5. Проверка**

Система проверяет:

1. есть текст вопроса;  
2. есть минимум два варианта ответа;  
3. правильный ответ указан;  
4. правильный ответ указывает на непустой вариант;  
5. тема заполнена;  
6. баллы больше 0\.

---

# **20\. Тип вопроса: несколько правильных ответов**

## **20.1. Название в интерфейсе**

**Несколько правильных ответов**

## **20.2. Техническое значение**

`multiple_choice`

## **20.3. Поля**

Для этого типа нужны поля:

1. текст вопроса;  
2. вариант A;  
3. вариант B;  
4. вариант C;  
5. вариант D;  
6. правильные ответы;  
7. тема;  
8. подтема;  
9. баллы;  
10. объяснение, необязательно.

## **20.4. Правильный ответ**

Правильный ответ хранится как набор вариантов.

Пример:

`A,C,D`

В интерфейсе лучше показывать не текстовое поле, а чекбоксы:

1. A;  
2. B;  
3. C;  
4. D.

## **20.5. Проверка**

Система проверяет:

1. есть текст вопроса;  
2. есть минимум два варианта ответа;  
3. выбран хотя бы один правильный вариант;  
4. каждый правильный вариант указывает на непустой вариант;  
5. тема заполнена;  
6. баллы больше 0\.

## **20.6. Начисление баллов**

В MVP баллы начисляются только при полном совпадении.

Если правильный ответ:

`A,C`

А ученик выбрал:

`A`

Ответ считается неправильным.

Частичные баллы в MVP не делаем.

---

# **21\. Тип вопроса: короткий текстовый ответ**

## **21.1. Название в интерфейсе**

**Короткий ответ**

## **21.2. Техническое значение**

`short_text`

## **21.3. Поля**

Для этого типа нужны поля:

1. текст вопроса;  
2. правильный ответ;  
3. дополнительные допустимые ответы;  
4. тема;  
5. подтема;  
6. баллы;  
7. объяснение, необязательно.

## **21.4. Правильный ответ**

Правильный ответ может содержать несколько допустимых вариантов.

Пример:

`пришёл;пришел`

В интерфейсе лучше сделать подсказку:

**Если правильных вариантов несколько, укажите их через точку с запятой.**

## **21.5. Проверка**

Система проверяет:

1. есть текст вопроса;  
2. правильный ответ не пустой;  
3. тема заполнена;  
4. баллы больше 0\.

## **21.6. Нормализация**

При проверке ответа ученика система должна:

1. убрать пробелы в начале и конце;  
2. привести к нижнему регистру;  
3. заменить множественные пробелы на один;  
4. сравнить с допустимыми ответами.

В MVP не делаем:

1. AI-проверку;  
2. морфологическую проверку;  
3. fuzzy matching;  
4. ручную проверку.

---

# **22\. Кнопки формы вопроса**

На форме вопроса нужны кнопки:

1. **Сохранить**;  
2. **Сохранить и добавить ещё**;  
3. **Отменить**.

### **22.1. Сохранить**

Сохраняет вопрос и возвращает к списку вопросов.

### **22.2. Сохранить и добавить ещё**

Сохраняет вопрос, очищает форму и позволяет сразу добавить следующий вопрос.

Это важно, потому что готовых тестов пока нет и преподаватель может вводить вопросы вручную.

### **22.3. Отменить**

Возвращает к списку вопросов без сохранения изменений.

---

# **23\. Редактирование вопроса**

При редактировании вопроса открывается та же форма, что и при создании.

После сохранения система должна:

1. сохранить изменения;  
2. пересчитать максимальный балл теста;  
3. обновить количество вопросов, если нужно;  
4. вернуть преподавателя к списку вопросов на ту же позицию.

---

# **24\. Удаление вопроса**

При удалении вопроса система должна показать подтверждение:

**Удалить вопрос? Это действие уберёт вопрос из текущей версии теста. Уже завершённые результаты учеников не изменятся.**

Технически лучше использовать soft delete.

После удаления:

1. вопрос не показывается в тесте;  
2. максимальный балл пересчитывается;  
3. количество вопросов пересчитывается;  
4. старые попытки не меняются.

---

# **25\. Изменение порядка вопросов**

В MVP достаточно кнопок:

1. вверх;  
2. вниз.

Drag-and-drop можно не делать в первой версии.

После изменения порядка:

1. обновляется `order_index`;  
2. порядок в предпросмотре и тесте меняется;  
3. старые попытки не меняются.

---

# **26\. Темы и подтемы**

## **26.1. Тема**

Поле `topic` обязательно.

Без темы вопрос нельзя сохранить.

Причина: результат по темам является обязательной частью MVP.

## **26.2. Подтема**

Поле `subtopic` желательно, но необязательно.

# **31\. Импорт Excel/CSV**

Вкладка “Импорт” нужна для массовой загрузки вопросов.

---

## **31.1. Основной сценарий импорта**

Сценарий:

1. преподаватель открывает вкладку “Импорт”;  
2. скачивает шаблон;  
3. заполняет файл;  
4. загружает файл;  
5. выбирает режим импорта;  
6. система валидирует файл;  
7. система показывает ошибки и предупреждения;  
8. если критических ошибок нет, преподаватель подтверждает импорт;  
9. вопросы добавляются в тест;  
10. преподаватель может редактировать вопросы вручную.

---

## **31.2. Поддерживаемые форматы**

В MVP поддерживаем:

1. XLSX;  
2. CSV.

Рекомендуемый формат:

XLSX.

---

## **31.3. Колонки шаблона**

Шаблон должен содержать колонки:

1. `question_text`;  
2. `question_type`;  
3. `option_a`;  
4. `option_b`;  
5. `option_c`;  
6. `option_d`;  
7. `correct_answer`;  
8. `topic`;  
9. `subtopic`;  
10. `difficulty`;  
11. `points`;  
12. `source`;  
13. `explanation`.

---

## **31.4. Обязательные колонки**

Обязательные колонки:

1. `question_text`;  
2. `question_type`;  
3. `correct_answer`;  
4. `topic`;  
5. `points`.

Для `single_choice` и `multiple_choice` также нужны варианты ответа.

Для `short_text` варианты ответа не обязательны.

---

# **32\. Примеры строк импорта**

## **32.1. single\_choice**

`question_type = single_choice`

`correct_answer = B`

Пример:

| question\_text | question\_type | option\_a | option\_b | option\_c | option\_d | correct\_answer | topic | subtopic | points |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Укажите правильный вариант написания | single\_choice | деревянный | деревяный | деревяннный | деревяанный | A | Орфография | Н/НН | 1 |

---

## **32.2. multiple\_choice**

`question_type = multiple_choice`

`correct_answer = A,C`

Пример:

| question\_text | question\_type | option\_a | option\_b | option\_c | option\_d | correct\_answer | topic | subtopic | points |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Выберите слова с безударной проверяемой гласной | multiple\_choice | вода | собака | леса | пальто | A,C | Орфография | Безударные гласные | 2 |

---

## **32.3. short\_text**

`question_type = short_text`

`correct_answer = пришёл;пришел`

Пример:

| question\_text | question\_type | correct\_answer | topic | subtopic | points |
| ----- | ----- | ----- | ----- | ----- | ----- |
| Введите правильную форму слова “прийти” в прошедшем времени | short\_text | пришёл;пришел | Орфография | Е/Ё | 1 |

---

# **33\. Режимы импорта**

Если в тесте уже есть вопросы, система должна спросить:

**Как импортировать вопросы?**

Варианты:

1. добавить к текущим вопросам;  
2. заменить все вопросы.

---

## **33.1. Добавить к текущим вопросам**

Техническое значение:

`append`

Новые вопросы добавляются после существующих.

Это режим по умолчанию.

---

## **33.2. Заменить все вопросы**

Техническое значение:

`replace`

Текущие вопросы заменяются вопросами из файла.

Перед подтверждением нужно показать предупреждение:

**Текущие вопросы будут заменены вопросами из файла. Уже завершённые результаты учеников не изменятся.**

---

# **34\. Валидация импорта**

## **34.1. Критические ошибки**

Файл нельзя импортировать, если есть критические ошибки:

1. нет обязательной колонки;  
2. пустой `question_text`;  
3. пустой `question_type`;  
4. неизвестный `question_type`;  
5. пустой `correct_answer`;  
6. пустой `topic`;  
7. пустой `points`;  
8. `points` не число;  
9. `points` меньше или равен 0;  
10. для `single_choice` нет минимум двух вариантов ответа;  
11. для `single_choice` correct\_answer не A/B/C/D;  
12. для `single_choice` correct\_answer указывает на пустой вариант;  
13. для `multiple_choice` нет минимум двух вариантов ответа;  
14. для `multiple_choice` correct\_answer содержит значения не A/B/C/D;  
15. для `multiple_choice` correct\_answer указывает на пустой вариант;  
16. для `short_text` correct\_answer пустой.

---

## **34.2. Предупреждения**

Файл можно импортировать, но нужно показать предупреждения:

1. нет `explanation`;  
2. нет `subtopic`;  
3. нет `difficulty`;  
4. возможный дубль вопроса;  
5. слишком длинный текст вопроса;  
6. все вопросы относятся к одной теме.

---

## **34.3. Частичный импорт**

Частичный импорт запрещён.

Если есть критические ошибки, не импортируется ничего.

---

# **35\. Экран ошибок импорта**

После проверки файла система должна показать:

1. количество строк;  
2. количество валидных строк;  
3. количество строк с ошибками;  
4. количество предупреждений;  
5. список ошибок;  
6. список предупреждений.

Для каждой ошибки показать:

1. номер строки;  
2. поле;  
3. тип ошибки;  
4. понятное описание.

Пример:

**Строка 12, поле correct\_answer: указан вариант D, но option\_d пустой.**

---

# **36\. Предпросмотр импортированных вопросов**

Перед подтверждением импорта система должна показать preview:

1. номер;  
2. текст вопроса;  
3. тип вопроса;  
4. правильный ответ;  
5. тема;  
6. подтема;  
7. баллы.

Если ошибок нет, доступна кнопка:

**Импортировать вопросы**

# **37\. Предпросмотр теста**

Предпросмотр теста входит в MVP.

---

## **37.1. Цель предпросмотра**

Преподаватель должен увидеть тест так, как его увидит ученик.

---

## **37.2. Что показывает предпросмотр**

Предпросмотр должен показывать:

1. экран перед стартом;  
2. вопросы;  
3. варианты ответов;  
4. поле короткого ответа;  
5. порядок вопросов;  
6. таймер в демонстрационном режиме;  
7. навигацию назад/вперёд;  
8. экран завершения, можно без настоящего результата.

---

## **37.3. Что предпросмотр не делает**

Предпросмотр не должен:

1. требовать оплату;  
2. создавать настоящую попытку;  
3. списывать доступ;  
4. попадать в результаты;  
5. создавать оплату;  
6. создавать Access.

---

# **38\. Настройки оценивания**

Во вкладке “Настройки оценивания” нужно настроить, как считается результат.

---

## **38.1. Поля**

Поля:

1. режим теста;  
2. шкала оценивания, если режим ЦЭ/ЦТ;  
3. показывать тестовый балл 0-100;  
4. показывать процент;  
5. показывать правильные ответы;  
6. показывать результат по темам;  
7. показывать рекомендации.

---

## **38.2. Тренировочный режим**

В тренировочном режиме результат считается так:

1. сумма баллов за правильные ответы;  
2. максимальная сумма баллов;  
3. процент;  
4. уровень;  
5. темы;  
6. ошибки.

---

## **38.3. Режим ЦЭ/ЦТ**

В режиме ЦЭ/ЦТ:

1. считается первичный балл;  
2. если подключена шкала, считается тестовый балл 0-100;  
3. показываются темы и ошибки.

Если шкала не подключена, можно показывать только первичный балл.

---

## **38.4. Проверка шкалы перед публикацией**

Если включён режим ЦЭ/ЦТ и включён показ тестового балла 0-100, тест нельзя опубликовать без шкалы.

Если максимальный балл теста не совпадает с максимальным первичным баллом шкалы, тест нельзя опубликовать.

---

# **39\. Настройки доступа**

Во вкладке “Настройки доступа” преподаватель настраивает коммерческие параметры теста.

---

## **39.1. Поля**

Поля:

1. цена;  
2. валюта;  
3. количество попыток после покупки;  
4. срок доступа после покупки;  
5. доступен ли тест для покупки;  
6. доступна ли активация по коду.

---

## **39.2. Значения для MVP**

По умолчанию:

1. покупка \= один тест;  
2. попытки \= 1;  
3. срок доступа \= 7 дней;  
4. активация по коду доступна;  
5. ручная выдача доступна.

---

## **39.3. Быстрые действия**

Можно добавить быстрые действия:

1. создать код доступа для этого теста;  
2. вручную выдать доступ к этому тесту;  
3. перейти к оплатам по этому тесту;  
4. перейти к результатам по этому тесту.

---

# **40\. Проверка готовности к публикации**

Перед публикацией теста система должна запускать чеклист.

---

## **40.1. Блокирующие ошибки**

Тест нельзя опубликовать, если:

1. нет названия;  
2. нет цены;  
3. нет времени прохождения;  
4. нет срока доступа;  
5. нет вопросов;  
6. есть вопросы без правильного ответа;  
7. есть вопросы без темы;  
8. есть вопросы без баллов;  
9. есть вопросы с некорректным типом;  
10. есть вопросы с некорректными вариантами ответа;  
11. включена шкала ЦЭ/ЦТ, но шкала не выбрана;  
12. максимальный балл теста не совпадает со шкалой, если шкала включена.

---

## **40.2. Предупреждения**

Тест можно опубликовать, но нужно показать предупреждения:

1. у части вопросов нет объяснений;  
2. у части вопросов нет подтем;  
3. вопросов слишком мало;  
4. все вопросы из одной темы;  
5. нет полного описания;  
6. нет краткого описания;  
7. цена слишком низкая или не задана как ожидаемая, если есть бизнес-правило;  
8. слишком короткое время прохождения.

---

## **40.3. Экран проверки**

Экран проверки должен показывать:

1. можно ли публиковать тест;  
2. список ошибок;  
3. список предупреждений;  
4. кнопку “Исправить”;  
5. кнопку “Опубликовать”, если ошибок нет.

---

# **41\. Публикация теста**

При публикации:

1. статус теста меняется на `published`;  
2. сохраняется `published_at`;  
3. тест появляется в каталоге;  
4. тест становится доступен для покупки;  
5. тест становится доступен для активации по коду, если это включено.

---

# **42\. Скрытие теста**

Если тест скрыт:

1. он не показывается в каталоге;  
2. новые ученики не могут его купить;  
3. новые коды лучше не создавать;  
4. старые результаты сохраняются;  
5. админ всё ещё может видеть тест в админке.

---

# **43\. Результаты внутри теста**

Во вкладке “Результаты” нужно показать попытки по конкретному тесту.

Таблица должна содержать:

1. email ученика;  
2. дата старта;  
3. дата завершения;  
4. статус попытки;  
5. балл;  
6. максимальный балл;  
7. процент;  
8. уровень;  
9. действие “Открыть попытку”.

---

## **43.1. Детальная попытка**

Детальная попытка должна показывать:

1. данные ученика;  
2. данные теста;  
3. итоговый результат;  
4. результат по темам;  
5. список вопросов;  
6. ответ ученика;  
7. правильный ответ;  
8. правильность;  
9. баллы за вопрос;  
10. тему;  
11. подтему.

---

# **44\. Защита старых результатов**

После редактирования опубликованного теста:

1. новые попытки используют новую версию теста;  
2. старые попытки остаются неизменными;  
3. старые результаты не пересчитываются;  
4. ответы старых учеников не ломаются.

Это обеспечивается через snapshot теста при старте попытки.

# **51\. Итог**

Admin Test Builder v1 должен дать преподавателю полный контроль над созданием первого коммерческого теста.

В первой версии важно не делать большую образовательную платформу, а сделать удобный и надёжный конструктор:

создать тест → добавить вопросы вручную или через Excel/CSV → проверить → настроить доступ и оценивание → посмотреть предпросмотр → опубликовать.

Ключевые требования:

1. ручное создание вопросов входит в MVP;  
2. импорт Excel/CSV входит в MVP;  
3. поддерживаются три типа вопросов;  
4. тема обязательна;  
5. объяснение необязательно;  
6. предпросмотр входит в MVP;  
7. публикация возможна только после проверки;  
8. старые результаты защищены через snapshot.
