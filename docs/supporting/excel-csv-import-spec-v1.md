# **Excel/CSV Import Spec v1**

## **1\. Назначение документа**

Документ описывает логику импорта вопросов из Excel/CSV для MVP v1.1 сервиса онлайн-тестов по русскому языку для подготовки к ЦЭ/ЦТ.

Импорт нужен, чтобы преподаватель мог массово загружать вопросы в тест без участия разработчика.

Документ фиксирует:

1. поддерживаемые форматы файлов;  
2. структуру шаблона;  
3. обязательные и необязательные поля;  
4. правила для разных типов вопросов;  
5. режимы импорта;  
6. валидацию файла;  
7. ошибки и предупреждения;  
8. предпросмотр перед импортом;  
9. правила сохранения вопросов;  
10. API для импорта;  
11. критерии готовности.

---

## **2\. Главная цель импорта**

Цель импорта:

Преподаватель может скачать шаблон, заполнить вопросы, загрузить файл, увидеть ошибки, подтвердить импорт и получить готовые вопросы в тесте.

Импорт должен быть понятным для преподавателя, а не только техническим загрузчиком файла.

---

## **3\. Роль импорта в MVP**

В MVP v1.1 есть два способа создания вопросов:

1. вручную в админке;  
2. через Excel/CSV.

Оба способа обязательны.

После импорта преподаватель должен иметь возможность вручную редактировать любые загруженные вопросы.

---

## **4\. Поддерживаемые форматы**

В первой версии поддерживаются:

1. `.xlsx`;  
2. `.csv`.

Основной рекомендуемый формат:

`.xlsx`

CSV поддерживается как дополнительный формат.

---

## **5\. Ограничения MVP**

В MVP импорт поддерживает только три типа вопросов:

1. `single_choice`;  
2. `multiple_choice`;  
3. `short_text`.

В MVP не поддерживаются:

1. развёрнутые ответы;  
2. сочинения;  
3. ручная проверка;  
4. задания на сопоставление;  
5. drag-and-drop;  
6. задания на сортировку;  
7. частичные баллы;  
8. AI-проверка;  
9. импорт изображений;  
10. импорт аудио;  
11. импорт из Word;  
12. импорт из PDF.

---

## **6\. Пользовательский сценарий импорта**

### **6.1. Основной flow**

1. Преподаватель открывает админку.  
2. Открывает нужный тест.  
3. Переходит во вкладку **Импорт**.  
4. Скачивает шаблон Excel/CSV.  
5. Заполняет файл вопросами.  
6. Загружает файл в систему.  
7. Выбирает режим импорта:

   * добавить к текущим вопросам;  
   * заменить все вопросы.  
8. Система валидирует файл.  
9. Система показывает ошибки и предупреждения.  
10. Если критических ошибок нет, преподаватель видит предпросмотр.  
11. Преподаватель нажимает **Импортировать вопросы**.  
12. Вопросы добавляются в тест.  
13. Преподаватель может редактировать вопросы вручную.  
14. Система пересчитывает количество вопросов и максимальный балл теста.

---

## **7\. Раздел импорта в админке**

В админке внутри теста должна быть вкладка:

**Импорт**

На вкладке должны быть:

1. кнопка **Скачать шаблон XLSX**;  
2. кнопка **Скачать шаблон CSV**;  
3. поле загрузки файла;  
4. выбор режима импорта;  
5. блок правил заполнения;  
6. блок результата проверки файла;  
7. блок ошибок;  
8. блок предупреждений;  
9. предпросмотр вопросов;  
10. кнопка **Импортировать вопросы**.

---

## **8\. Режимы импорта**

Если тест уже содержит вопросы, система должна спросить:

**Как импортировать вопросы?**

Доступные режимы:

1. добавить к текущим вопросам;  
2. заменить все вопросы.

---

### **8.1. Режим append**

Название в интерфейсе:

**Добавить к текущим вопросам**

Техническое значение:

`append`

Логика:

1. новые вопросы добавляются после уже существующих;  
2. существующие вопросы не изменяются;  
3. order\_index новых вопросов продолжается после последнего текущего вопроса;  
4. старые результаты учеников не меняются.

Это режим по умолчанию.

---

### **8.2. Режим replace**

Название в интерфейсе:

**Заменить все вопросы**

Техническое значение:

`replace`

Логика:

1. текущие вопросы теста удаляются или soft-delete;  
2. вопросы из файла становятся новой текущей версией вопросов;  
3. order\_index начинается с 1;  
4. старые результаты учеников не меняются, потому что попытки хранят snapshot.

Перед подтверждением нужно показать предупреждение:

**Текущие вопросы будут заменены вопросами из файла. Уже завершённые результаты учеников не изменятся.**

---

## **9\. Частичный импорт**

Частичный импорт запрещён.

Если в файле есть хотя бы одна критическая ошибка:

1. файл не импортируется;  
2. вопросы не создаются;  
3. текущие вопросы не изменяются;  
4. система показывает список ошибок;  
5. преподаватель должен исправить файл и загрузить заново.

Причина: частичный импорт может привести к сломанному тесту.

---

## **10\. Шаблон файла**

Файл должен иметь одну таблицу с вопросами.

Каждая строка \= один вопрос.

Каждая колонка \= поле вопроса.

---

## **11\. Колонки шаблона**

Шаблон должен содержать следующие колонки:

1. `question_text`;  
2. `question_type`;  
3. `option_a`;  
4. `option_b`;  
5. `option_c`;  
6. `option_d`;  
7. `correct_answer`;  
8. `topic`;  
9. `subtopic`;  
10. `difficulty`;  
11. `points`;  
12. `source`;  
13. `explanation`.

---

## **12\. Описание колонок**

### **12.1. question\_text**

Назначение:

текст вопроса.

Обязательность:

обязательно.

Тип:

текст.

Пример:

`Укажите правильный вариант написания слова.`

---

### **12.2. question\_type**

Назначение:

тип вопроса.

Обязательность:

обязательно.

Допустимые значения:

1. `single_choice`;  
2. `multiple_choice`;  
3. `short_text`.

Пример:

`single_choice`

---

### **12.3. option\_a**

Назначение:

вариант ответа A.

Обязательность:

1. для `single_choice` обязательно, если используется как один из минимум двух вариантов;  
2. для `multiple_choice` обязательно, если используется как один из минимум двух вариантов;  
3. для `short_text` не требуется.

Пример:

`деревянный`

---

### **12.4. option\_b**

Назначение:

вариант ответа B.

Обязательность:

1. для `single_choice` обязательно, если используется как один из минимум двух вариантов;  
2. для `multiple_choice` обязательно, если используется как один из минимум двух вариантов;  
3. для `short_text` не требуется.

Пример:

`деревяный`

---

### **12.5. option\_c**

Назначение:

вариант ответа C.

Обязательность:

необязательно.

Пример:

`деревяннный`

---

### **12.6. option\_d**

Назначение:

вариант ответа D.

Обязательность:

необязательно.

Пример:

`деревяанный`

---

### **12.7. correct\_answer**

Назначение:

правильный ответ.

Обязательность:

обязательно.

Формат зависит от типа вопроса.

Для `single_choice`:

`A`

Для `multiple_choice`:

`A,C`

Для `short_text`:

`пришёл;пришел`

---

### **12.8. topic**

Назначение:

тема вопроса.

Обязательность:

обязательно.

Причина:

по теме строится результат ученика.

Примеры:

1. `Орфография`;  
2. `Пунктуация`;  
3. `Грамматика`;  
4. `Лексика`;  
5. `Речевые нормы`;  
6. `Работа с текстом`;  
7. `Ударение`.

---

### **12.9. subtopic**

Назначение:

подтема вопроса.

Обязательность:

необязательно, но желательно.

Примеры:

1. `Н/НН`;  
2. `НЕ/НИ`;  
3. `Причастный оборот`;  
4. `Деепричастный оборот`;  
5. `Сложноподчинённое предложение`;  
6. `Паронимы`;  
7. `Управление`.

---

### **12.10. difficulty**

Назначение:

сложность вопроса.

Обязательность:

необязательно.

Допустимые значения:

1. `easy`;  
2. `medium`;  
3. `hard`.

Значение по умолчанию:

`medium`

В MVP сложность не обязана влиять на расчёт результата.

---

### **12.11. points**

Назначение:

количество баллов за вопрос.

Обязательность:

обязательно.

Тип:

целое число больше 0\.

Примеры:

1. `1`;  
2. `2`;  
3. `3`.

---

### **12.12. source**

Назначение:

источник или комментарий для преподавателя.

Обязательность:

необязательно.

Ученику не показывается.

Пример:

`ЦТ 2023, вариант 2`

---

### **12.13. explanation**

Назначение:

объяснение правильного ответа.

Обязательность:

необязательно.

Если заполнено, можно показать ученику после завершения теста.

Если не заполнено, в результате не нужно показывать пустой блок.

---

## **13\. Обязательные колонки**

Для всех типов вопросов обязательны:

1. `question_text`;  
2. `question_type`;  
3. `correct_answer`;  
4. `topic`;  
5. `points`.

Для `single_choice` и `multiple_choice` также должны быть минимум два непустых варианта ответа среди:

1. `option_a`;  
2. `option_b`;  
3. `option_c`;  
4. `option_d`.

Для `short_text` варианты ответа не нужны.

---

## **14\. Тип вопроса single\_choice**

### **14.1. Назначение**

Вопрос с одним правильным ответом.

Ученик выбирает один вариант из A/B/C/D.

---

### **14.2. Значение question\_type**

`single_choice`

---

### **14.3. Формат correct\_answer**

Правильный ответ должен быть одним значением:

1. `A`;  
2. `B`;  
3. `C`;  
4. `D`.

Пример:

`B`

---

### **14.4. Правила**

1. Должен быть текст вопроса.  
2. Должен быть тип `single_choice`.  
3. Должно быть минимум два варианта ответа.  
4. Должен быть один правильный ответ.  
5. Правильный ответ должен указывать на непустой вариант.  
6. Должна быть тема.  
7. Должны быть баллы больше 0\.

---

### **14.5. Пример строки**

| question\_text | question\_type | option\_a | option\_b | option\_c | option\_d | correct\_answer | topic | subtopic | difficulty | points | source | explanation |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Укажите правильный вариант написания | single\_choice | деревянный | деревяный | деревяннный | деревяанный | A | Орфография | Н/НН | medium | 1 |  |  |

---

## **15\. Тип вопроса multiple\_choice**

### **15.1. Назначение**

Вопрос с несколькими правильными ответами.

Ученик может выбрать несколько вариантов.

---

### **15.2. Значение question\_type**

`multiple_choice`

---

### **15.3. Формат correct\_answer**

Правильный ответ хранится как список вариантов через запятую.

Пример:

`A,C`

Другой пример:

`A,C,D`

---

### **15.4. Правила**

1. Должен быть текст вопроса.  
2. Должен быть тип `multiple_choice`.  
3. Должно быть минимум два варианта ответа.  
4. Должен быть хотя бы один правильный вариант.  
5. Каждый правильный вариант должен быть одним из A/B/C/D.  
6. Каждый правильный вариант должен указывать на непустой option.  
7. Должна быть тема.  
8. Должны быть баллы больше 0\.

---

### **15.5. Начисление баллов**

В MVP баллы начисляются только при полном совпадении.

Если правильный ответ:

`A,C`

А ученик выбрал:

`A`

Ответ считается неправильным.

Частичные баллы в MVP не начисляются.

---

### **15.6. Пример строки**

| question\_text | question\_type | option\_a | option\_b | option\_c | option\_d | correct\_answer | topic | subtopic | difficulty | points | source | explanation |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Выберите слова с безударной проверяемой гласной | multiple\_choice | вода | собака | леса | пальто | A,C | Орфография | Безударные гласные | medium | 2 |  |  |

---

## **16\. Тип вопроса short\_text**

### **16.1. Назначение**

Вопрос с коротким текстовым ответом.

Ученик вводит слово, форму слова, число или короткую фразу.

---

### **16.2. Значение question\_type**

`short_text`

---

### **16.3. Формат correct\_answer**

Правильный ответ может быть одним вариантом:

`пришёл`

Или несколькими допустимыми вариантами через точку с запятой:

`пришёл;пришел`

---

### **16.4. Правила**

1. Должен быть текст вопроса.  
2. Должен быть тип `short_text`.  
3. Должен быть правильный ответ.  
4. Варианты option\_a-d не обязательны.  
5. Должна быть тема.  
6. Должны быть баллы больше 0\.

---

### **16.5. Нормализация ответа ученика**

При проверке ответа система должна:

1. убрать пробелы в начале и конце;  
2. привести к нижнему регистру;  
3. заменить множественные пробелы на один;  
4. сравнить с допустимыми ответами.

---

### **16.6. Что не делаем в MVP**

В MVP не делаем:

1. AI-проверку;  
2. морфологическую проверку;  
3. fuzzy matching;  
4. ручную проверку;  
5. проверку развёрнутого ответа.

---

### **16.7. Пример строки**

| question\_text | question\_type | option\_a | option\_b | option\_c | option\_d | correct\_answer | topic | subtopic | difficulty | points | source | explanation |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Введите правильную форму слова “прийти” в прошедшем времени | short\_text |  |  |  |  | пришёл;пришел | Орфография | Е/Ё | medium | 1 |  |  |

---

## **17\. Нормализация данных при импорте**

Перед валидацией и сохранением система должна нормализовать данные.

---

### **17.1. Общая нормализация**

Для всех текстовых полей:

1. trim;  
2. убрать невидимые пробелы по возможности;  
3. пустые строки считать null;  
4. не менять смысловой текст вопроса.

---

### **17.2. question\_type**

Нормализация:

1. trim;  
2. lowercase.

Допустимые значения только:

1. `single_choice`;  
2. `multiple_choice`;  
3. `short_text`.

---

### **17.3. correct\_answer для single\_choice**

Нормализация:

1. trim;  
2. uppercase.

Пример:

`b` → `B`

---

### **17.4. correct\_answer для multiple\_choice**

Нормализация:

1. split по запятой;  
2. trim каждого значения;  
3. uppercase;  
4. удалить пустые элементы;  
5. удалить дубли;  
6. отсортировать по A/B/C/D;  
7. сохранить в формате `A,C`.

Пример:

`c, a` → `A,C`

---

### **17.5. correct\_answer для short\_text**

Нормализация:

1. split по `;`;  
2. trim каждого значения;  
3. lowercase;  
4. удалить пустые элементы;  
5. сохранить через `;`.

Пример:

`Пришёл ; пришел` → `пришёл;пришел`

---

### **17.6. difficulty**

Нормализация:

1. trim;  
2. lowercase.

Если пусто, поставить:

`medium`

Если заполнено, допустимые значения:

1. `easy`;  
2. `medium`;  
3. `hard`.

---

### **17.7. points**

Нормализация:

1. привести к числу;  
2. проверить, что это целое число;  
3. проверить, что больше 0\.

---

## **18\. Валидация файла**

Валидация делится на:

1. критические ошибки;  
2. предупреждения.

---

## **19\. Критические ошибки**

Критические ошибки блокируют импорт.

Если есть хотя бы одна критическая ошибка, кнопка **Импортировать вопросы** недоступна.

---

### **19.1. Ошибки структуры файла**

1. файл не читается;  
2. файл пустой;  
3. в файле нет строк с вопросами;  
4. нет обязательной колонки;  
5. название обязательной колонки написано неверно;  
6. файл имеет неподдерживаемый формат.

---

### **19.2. Общие ошибки строки**

1. пустой `question_text`;  
2. пустой `question_type`;  
3. неизвестный `question_type`;  
4. пустой `correct_answer`;  
5. пустой `topic`;  
6. пустой `points`;  
7. `points` не число;  
8. `points` меньше или равен 0\.

---

### **19.3. Ошибки single\_choice**

1. меньше двух вариантов ответа;  
2. `correct_answer` не A/B/C/D;  
3. `correct_answer` содержит больше одного варианта;  
4. `correct_answer` указывает на пустой вариант;  
5. все варианты ответа пустые.

---

### **19.4. Ошибки multiple\_choice**

1. меньше двух вариантов ответа;  
2. `correct_answer` содержит значение не A/B/C/D;  
3. `correct_answer` указывает на пустой вариант;  
4. `correct_answer` пустой после нормализации;  
5. все варианты ответа пустые.

---

### **19.5. Ошибки short\_text**

1. `correct_answer` пустой;  
2. `correct_answer` содержит только разделители;  
3. после нормализации не осталось ни одного допустимого ответа.

---

### **19.6. Ошибки difficulty**

Если `difficulty` заполнено, но значение не входит в список:

1. `easy`;  
2. `medium`;  
3. `hard`.

---

## **20\. Предупреждения**

Предупреждения не блокируют импорт.

Если есть только предупреждения, преподаватель может импортировать файл.

---

### **20.1. Предупреждения по качеству**

1. нет `explanation`;  
2. нет `subtopic`;  
3. нет `difficulty`, будет использовано `medium`;  
4. очень длинный текст вопроса;  
5. очень длинный вариант ответа;  
6. возможный дубль вопроса;  
7. все вопросы относятся к одной теме;  
8. слишком мало тем;  
9. слишком мало вопросов в файле;  
10. баллы сильно отличаются от большинства вопросов.

---

### **20.2. Предупреждения по объяснениям**

Так как объяснения необязательны в MVP, отсутствие explanation не блокирует импорт.

Текст предупреждения:

**Объяснение не заполнено. Ученик увидит правильный ответ, но не увидит разбор.**

---

### **20.3. Предупреждения по подтемам**

Так как подтемы необязательны, отсутствие subtopic не блокирует импорт.

Текст предупреждения:

**Подтема не заполнена. Рекомендации будут построены только по теме.**

---

## **24\. Предпросмотр перед импортом**

После успешной валидации система должна показать preview вопросов.

Preview нужен, чтобы преподаватель мог проверить файл до сохранения в базу.

---

### **24.1. Что показывать в preview**

Для каждого вопроса:

1. номер строки;  
2. текст вопроса;  
3. тип вопроса;  
4. варианты ответа, если есть;  
5. правильный ответ;  
6. тема;  
7. подтема;  
8. сложность;  
9. баллы;  
10. наличие объяснения.

---

### **24.2. Что не делать в preview**

Preview не должен:

1. создавать вопросы в базе;  
2. менять текущие вопросы теста;  
3. менять статус теста;  
4. пересчитывать количество вопросов теста;  
5. публиковать тест.

---

## **25\. Подтверждение импорта**

После preview преподаватель нажимает:

**Импортировать вопросы**

Система выполняет commit импорта.

---

### **25.1. Commit в режиме append**

Система:

1. берёт текущий максимальный `order_index`;  
2. создаёт новые вопросы после текущих;  
3. пересчитывает `questions_count`;  
4. пересчитывает `max_raw_score`;  
5. обновляет ImportJob;  
6. показывает сообщение об успехе.

---

### **25.2. Commit в режиме replace**

Система:

1. soft-delete текущие вопросы теста;  
2. создаёт новые вопросы из файла;  
3. начинает `order_index` с 1;  
4. пересчитывает `questions_count`;  
5. пересчитывает `max_raw_score`;  
6. обновляет ImportJob;  
7. показывает сообщение об успехе.

---

### **25.3. Транзакция**

Commit импорта обязательно выполняется в transaction.

Если что-то пошло не так:

1. новые вопросы не создаются частично;  
2. старые вопросы не заменяются частично;  
3. ImportJob получает статус failed;  
4. система показывает ошибку.

---

После commit каждая валидная строка создаёт запись в `questions`.

### **27.1. Маппинг колонок в question**

`option_b` → `questions.option_b`

`option_c` → `questions.option_c`

`order_index = row_number`

Для `single_choice`:

`full_match`

`full_match`

`exact_text`

1. `questions_count`;

3. `updated_at`.

Если тест уже опубликован, новые попытки должны использовать обновлённые вопросы.

Старые попытки не меняются из\-за snapshot.

## **29\. CSV-специфика**

CSV должен поддерживать:

1. UTF-8;  
2. разделитель `,`;  
3. разделитель `;`, если возможно;  
4. кавычки для текстов с разделителями;  
5. переносы строк внутри текста, если библиотека корректно поддерживает.

Рекомендация в интерфейсе:

**Для надёжной загрузки используйте XLSX. CSV может некорректно открываться из\-за кодировки или разделителей.**

---

## **30\. XLSX-специфика**

XLSX является основным форматом.

Правила:

1. читать первый лист файла;  
2. первая строка должна быть заголовками;  
3. начиная со второй строки идут вопросы;  
4. пустые строки игнорировать;  
5. объединённые ячейки не поддерживать;  
6. формулы не использовать как источник данных, лучше читать итоговое значение;  
7. изображения в файле игнорировать.

---

## **31\. Ограничения по размеру файла**

Для MVP рекомендуемые ограничения:

1. максимум 500 строк вопросов в одном файле;  
2. максимум 5 MB на файл;  
3. максимум 4 варианта ответа на вопрос.

Если файл больше лимита, показать ошибку:

**Файл слишком большой. Разделите вопросы на несколько файлов.**

## **36\. Безопасность**

Требования:

1. импорт доступен только администратору;  
2. ученик не может загружать файлы;  
3. проверять тип файла;  
4. проверять размер файла;  
5. не выполнять формулы из Excel как код;  
6. не сохранять файл как публичный ресурс;  
7. не доверять данным из файла без валидации;  
8. все вопросы перед сохранением проходят backend-валидацию;  
9. commit импорта выполняется в transaction.

## **38\. Edge cases**

### **38.1. Файл пустой**

Показать ошибку:

**Файл пустой. Добавьте вопросы и загрузите файл повторно.**

---

### **38.2. Нет обязательной колонки**

Показать ошибку:

**В файле отсутствует обязательная колонка: question\_text.**

---

### **38.3. Неверный тип вопроса**

Показать ошибку:

**Неизвестный тип вопроса. Допустимые значения: single\_choice, multiple\_choice, short\_text.**

---

### **38.4. Правильный ответ указывает на пустой вариант**

Показать ошибку:

**Указан вариант D, но option\_d пустой.**

---

### **38.5. В файле есть дубли вопросов**

Показать предупреждение:

**Возможно, этот вопрос повторяется. Проверьте файл перед импортом.**

Не блокировать импорт.

---

### **38.6. Нет объяснений**

Показать предупреждение.

Не блокировать импорт.

---

### **38.7. Нет подтем**

Показать предупреждение.

Не блокировать импорт.

---

### **38.8. Ошибка во время commit**

Если во время сохранения произошла ошибка:

1. откатить transaction;  
2. не создавать часть вопросов;  
3. сохранить ошибку в ImportJob;  
4. показать сообщение:

**Не удалось импортировать вопросы. Попробуйте ещё раз или обратитесь к администратору.**

---

### **38.9. Replace для опубликованного теста**

Разрешить, но показать предупреждение:

**Вы заменяете вопросы в опубликованном тесте. Новые ученики будут проходить новую версию теста. Уже завершённые попытки не изменятся.**

---

### **38.10. Append для опубликованного теста**

Разрешить, но показать предупреждение:

**Вы добавляете вопросы в опубликованный тест. Новые ученики будут проходить обновлённую версию теста. Уже завершённые попытки не изменятся.**

---

## **39\. Тексты подсказок в интерфейсе**

### **39.1. Подсказка перед загрузкой**

**Загрузите XLSX или CSV-файл с вопросами. Сначала скачайте шаблон и заполните его по примеру.**

---

### **39.2. Подсказка про типы вопросов**

**В первой версии поддерживаются три типа вопросов: один правильный ответ, несколько правильных ответов и короткий текстовый ответ.**

### **39.3. Подсказка про correct\_answer**

**Для одного правильного ответа укажите A, B, C или D. Для нескольких правильных ответов укажите варианты через запятую, например A,C. Для короткого ответа укажите допустимые ответы через точку с запятой.**

---

### **39.4. Подсказка про темы**

**Тема обязательна. По темам ученик увидит результат после прохождения теста.**

---

### **39.5. Подсказка про объяснения**

**Объяснение необязательно. Если оно заполнено, его можно показать ученику после завершения теста.**

Импорт считается готовым, если:

1. админ может скачать XLSX-шаблон;  
2. админ может скачать CSV-шаблон;  
3. админ может загрузить XLSX-файл;  
4. админ может загрузить CSV-файл;

7. система распознаёт `multiple_choice`;

9. система проверяет обязательные колонки;

18. частичный импорт невозможен;  
19. админ может выбрать append;

25. после импорта вопросы можно редактировать вручную;  
26. после импорта пересчитывается количество вопросов;  
27. после импорта пересчитывается максимальный балл;  
28. ImportJob сохраняет результат проверки;  
29. commit импорта выполняется в transaction;  
30. импорт доступен только админу.

## **43\. Итог**

Excel/CSV Import v1 должен позволить преподавателю без разработчика массово загружать вопросы в тест.

Ключевые требования:

1. XLSX как основной формат;  
2. CSV как дополнительный формат;  
3. три типа вопросов: single\_choice, multiple\_choice, short\_text;  
4. обязательная тема;  
5. обязательные баллы;  
6. объяснение необязательно;  
7. режимы append и replace;  
8. запрет частичного импорта;  
9. понятные ошибки по строкам;  
10. предпросмотр перед сохранением;  
11. ручное редактирование после импорта;  
12. защита старых результатов через snapshot попытки.
