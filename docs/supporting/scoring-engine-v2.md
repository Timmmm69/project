# **Scoring Engine v2**

## **1\. Назначение документа**

Документ описывает логику проверки ответов, начисления баллов, расчёта результата и формирования рекомендаций в MVP v1.1 сервиса онлайн-тестов по русскому языку для подготовки к ЦЭ/ЦТ.

Документ фиксирует:

1. режимы оценивания;  
2. типы вопросов;  
3. правила проверки ответов;  
4. правила начисления баллов;  
5. расчёт первичного балла;  
6. расчёт процента;  
7. расчёт уровня;  
8. расчёт результата по темам;  
9. расчёт рекомендаций;  
10. поддержку шкал ЦЭ/ЦТ 0-100;  
11. snapshot оценивания;  
12. edge cases;  
13. API и acceptance criteria.

---

## **2\. Главная цель Scoring Engine**

Scoring Engine должен автоматически проверить ответы ученика после завершения теста и сформировать понятный результат.

Результат должен быть полезен ученику и преподавателю.

Ученик должен понять:

1. сколько баллов набрал;  
2. какие ответы были неправильными;  
3. какие правильные ответы;  
4. какие темы просели;  
5. что повторить.

Преподаватель должен понять:

1. какой результат у ученика;  
2. где ученик ошибся;  
3. какие темы вызывают сложности;  
4. насколько тест был пройден успешно.

---

## **3\. Основные принципы**

1. Результат считается только на backend.  
2. Frontend не должен сам определять правильность ответов.  
3. Правильные ответы нельзя отдавать ученику до завершения теста.  
4. После завершения попытки результат фиксируется.  
5. Завершённые попытки не пересчитываются автоматически после редактирования теста.  
6. При старте попытки создаётся snapshot теста.  
7. Scoring Engine считает результат по snapshot, а не по текущей версии теста.  
8. В MVP нет частичных баллов.  
9. В MVP нет ручной проверки.  
10. В MVP нет AI-проверки.  
11. В MVP поддерживаются три типа вопросов:

    * `single_choice`;  
    * `multiple_choice`;  
    * `short_text`.

---

## **4\. Режимы оценивания**

В первой версии нужны два режима оценивания:

1. тренировочный режим;  
2. режим ЦЭ/ЦТ.

Техническое поле:

`test.mode`

Возможные значения:

1. `training`;  
2. `ce_ct`.

---

## **5\. Тренировочный режим**

Техническое значение:

`training`

В тренировочном режиме система считает:

1. первичный балл;  
2. максимальный первичный балл;  
3. процент выполнения;  
4. уровень результата;  
5. результат по темам;  
6. список ошибок;  
7. правильные ответы;  
8. рекомендации по слабым темам.

Тренировочный режим не требует шкалы 0-100.

---

## **6\. Режим ЦЭ/ЦТ**

Техническое значение:

`ce_ct`

В режиме ЦЭ/ЦТ система считает:

1. первичный балл;  
2. максимальный первичный балл;  
3. процент;  
4. результат по темам;  
5. ошибки;  
6. правильные ответы;  
7. тестовый балл 0-100, если подключена шкала.

Важно: в интерфейсе нельзя писать, что результат является официальным результатом ЦЭ/ЦТ.

Допустимая формулировка:

**Тренировочный расчёт по таблице соответствия первичных и тестовых баллов.**

---

## **7\. Что входит в MVP**

В MVP входит:

1. автоматическая проверка `single_choice`;  
2. автоматическая проверка `multiple_choice`;  
3. автоматическая проверка `short_text`;  
4. полный балл или 0 за вопрос;  
5. расчёт первичного балла;  
6. расчёт процента;  
7. расчёт уровня;  
8. расчёт результата по темам;  
9. список ошибок;  
10. правильные ответы после завершения;  
11. рекомендации по темам и подтемам;  
12. архитектура под шкалу ЦЭ/ЦТ 0-100;  
13. snapshot scoring-логики.

---

## **8\. Что не входит в MVP**

В MVP не входит:

1. частичное начисление баллов;  
2. ручная проверка преподавателем;  
3. AI-проверка;  
4. проверка сочинений;  
5. проверка развёрнутых ответов;  
6. fuzzy matching для коротких ответов;  
7. морфологическая проверка;  
8. сложное сопоставление;  
9. задания на сортировку;  
10. drag-and-drop задания;  
11. автоматический пересчёт старых результатов после изменения теста.

---

## **9\. Основные сущности**

Scoring Engine использует следующие сущности:

1. `tests`;  
2. `questions`;  
3. `attempts`;  
4. `answers`;  
5. `scoring_schemes`;  
6. `scoring_scales`.

---

## **10\. Поля tests, связанные с оцениванием**

В `tests` должны быть поля:

1. `mode`;  
2. `max_raw_score`;  
3. `scoring_scheme_id`;  
4. `show_scaled_score`;  
5. `show_percent`;  
6. `show_correct_answers`;  
7. `show_topic_result`;  
8. `show_recommendations`.

### **10.1. mode**

Возможные значения:

1. `training`;  
2. `ce_ct`.

### **10.2. max\_raw\_score**

Максимальный первичный балл теста.

Считается как сумма `points` всех активных вопросов теста.

### **10.3. scoring\_scheme\_id**

Ссылка на шкалу оценивания.

Может быть пустой, если тест работает только в тренировочном режиме или если шкала пока не подключена.

### **10.4. show\_scaled\_score**

Показывать ли тестовый балл 0-100.

### **10.5. show\_percent**

Показывать ли процент выполнения.

### **10.6. show\_correct\_answers**

Показывать ли правильные ответы после завершения.

### **10.7. show\_topic\_result**

Показывать ли результат по темам.

### **10.8. show\_recommendations**

Показывать ли рекомендации.

---

## **11\. Поля questions, связанные с оцениванием**

В `questions` должны быть поля:

1. `question_type`;  
2. `correct_answer`;  
3. `points`;  
4. `scoring_rule`;  
5. `topic`;  
6. `subtopic`;  
7. `explanation`.

---

## **12\. question\_type**

В MVP поддерживаются:

1. `single_choice`;  
2. `multiple_choice`;  
3. `short_text`.

---

## **13\. scoring\_rule**

Возможные значения:

1. `full_match`;  
2. `exact_text`;  
3. `partial_match`;  
4. `manual`.

В MVP используются:

1. `full_match`;  
2. `exact_text`.

`partial_match` и `manual` закладываются на будущее, но не используются в первой версии.

---

## **14\. Маппинг question\_type → scoring\_rule**

### **14.1. single\_choice**

`question_type = single_choice`

`scoring_rule = full_match`

### **14.2. multiple\_choice**

`question_type = multiple_choice`

`scoring_rule = full_match`

### **14.3. short\_text**

`question_type = short_text`

`scoring_rule = exact_text`

---

## **15\. Общая формула результата**

Scoring Engine считает:

`raw_score = сумма points_earned по всем вопросам`

`max_raw_score = сумма max_points по всем вопросам`

`percent = raw_score / max_raw_score * 100`

Если `max_raw_score = 0`, результат считать нельзя. Такой тест нельзя публиковать.

---

## **16\. Начисление баллов**

В MVP за каждый вопрос есть только два варианта:

1. полный балл;  
2. 0 баллов.

Частичные баллы не начисляются.

Если ответ правильный:

`points_earned = max_points`

Если ответ неправильный:

`points_earned = 0`

Если ответ пустой:

`points_earned = 0`

---

## **17\. Проверка single\_choice**

### **17.1. Суть**

Ученик выбирает один вариант ответа.

Пример правильного ответа:

`B`

Пример ответа ученика:

`B`

---

### **17.2. Нормализация**

Перед сравнением:

1. привести ответ к строке;  
2. trim;  
3. uppercase.

---

### **17.3. Правило проверки**

Ответ правильный, если:

`selected_answer == correct_answer`

---

### **17.4. Пример**

Правильный ответ:

`B`

Ответ ученика:

`b`

После нормализации:

`B`

Результат:

1. `is_correct = true`;  
2. `points_earned = max_points`.

---

### **17.5. Ошибочный ответ**

Правильный ответ:

`B`

Ответ ученика:

`A`

Результат:

1. `is_correct = false`;  
2. `points_earned = 0`.

---

## **18\. Проверка multiple\_choice**

### **18.1. Суть**

Ученик выбирает несколько вариантов ответа.

Пример правильного ответа:

`A,C,D`

Пример ответа ученика:

`C,A,D`

---

### **18.2. Нормализация**

Для правильного ответа и ответа ученика:

1. split по запятой;  
2. trim каждого элемента;  
3. uppercase;  
4. удалить пустые элементы;  
5. удалить дубли;  
6. отсортировать по A/B/C/D;  
7. собрать обратно в строку через запятую.

---

### **18.3. Правило проверки**

Ответ правильный, если нормализованный набор ученика полностью совпадает с нормализованным правильным набором.

---

### **18.4. Пример правильного ответа**

Правильный ответ:

`A,C`

Ответ ученика:

`C,A`

После нормализации:

`A,C`

Результат:

1. `is_correct = true`;  
2. `points_earned = max_points`.

---

### **18.5. Пример неполного ответа**

Правильный ответ:

`A,C`

Ответ ученика:

`A`

Результат:

1. `is_correct = false`;  
2. `points_earned = 0`.

---

### **18.6. Пример лишнего варианта**

Правильный ответ:

`A,C`

Ответ ученика:

`A,C,D`

Результат:

1. `is_correct = false`;  
2. `points_earned = 0`.

---

### **18.7. Частичные баллы**

В MVP частичные баллы не начисляются.

Даже если ученик выбрал часть правильных вариантов, но не весь набор, ответ считается неправильным.

---

## **19\. Проверка short\_text**

### **19.1. Суть**

Ученик вводит короткий текстовый ответ.

Пример правильных ответов:

`пришёл;пришел`

Ответ ученика:

`Пришёл`

---

### **19.2. Нормализация ответа ученика**

Перед сравнением:

1. привести к строке;  
2. trim;  
3. lowercase;  
4. заменить несколько пробелов подряд на один;  
5. сохранить буквы `ё` и `е` как разные символы, если они не указаны оба в correct\_answer.

---

### **19.3. Нормализация correct\_answer**

Если правильных вариантов несколько, они разделяются через `;`.

Перед сравнением:

1. split по `;`;  
2. trim каждого варианта;  
3. lowercase;  
4. удалить пустые элементы;  
5. заменить несколько пробелов подряд на один.

---

### **19.4. Правило проверки**

Ответ правильный, если нормализованный ответ ученика полностью совпадает хотя бы с одним нормализованным правильным вариантом.

---

### **19.5. Пример**

Правильный ответ:

`пришёл;пришел`

Ответ ученика:

`Пришёл`

После нормализации:

`пришёл`

Результат:

1. `is_correct = true`;  
2. `points_earned = max_points`.

---

### **19.6. Что не проверяем в MVP**

В MVP не проверяем:

1. опечатки;  
2. похожие формы слова;  
3. синонимы;  
4. морфологические варианты, если они не указаны в correct\_answer;  
5. ответы с ошибками;  
6. развёрнутые ответы.

---

## **20\. Пустые ответы**

Если ученик не ответил на вопрос:

1. `selected_answer = null` или пустая строка;  
2. `is_correct = false`;  
3. `points_earned = 0`.

Пустые ответы должны попасть в результат как ошибки.

---

## **21\. Завершение теста**

Scoring Engine запускается, когда попытка получает финальный статус:

1. `completed`;  
2. `expired`.

---

## **22\. Статусы попытки**

Возможные статусы:

1. `started`;  
2. `completed`;  
3. `expired`;  
4. `cancelled`.

Scoring Engine не должен считать результат для статуса:

1. `started`;  
2. `cancelled`.

---

## **23\. Завершение вручную**

Если ученик нажал **Завершить тест**:

1. frontend отправляет запрос на завершение;  
2. backend блокирует дальнейшее изменение ответов;  
3. backend проверяет ответы;  
4. backend считает результат;  
5. attempt получает статус `completed`;  
6. результат становится доступен ученику.

---

## **24\. Автозавершение по таймеру**

Если время вышло:

1. frontend отправляет запрос на expire;  
2. backend проверяет, что время действительно вышло;  
3. backend блокирует изменение ответов;  
4. backend проверяет сохранённые ответы;  
5. пустые ответы считает неправильными;  
6. attempt получает статус `expired`;  
7. результат становится доступен ученику.

Backend не должен доверять только frontend-таймеру. Время нужно считать от `started_at`.

---

## **25\. Snapshot теста**

Scoring Engine должен считать результат по `test_snapshot_json`, сохранённому в момент старта попытки.

---

## **26\. Что должно быть в test\_snapshot\_json**

Snapshot должен содержать:

1. test\_id;  
2. title;  
3. subject;  
4. mode;  
5. duration\_minutes;  
6. max\_raw\_score;  
7. настройки показа результата;  
8. вопросы;  
9. order\_index;  
10. question\_type;  
11. options;  
12. correct\_answer;  
13. topic;  
14. subtopic;  
15. points;  
16. scoring\_rule;  
17. explanation;  
18. scoring\_scheme\_snapshot, если шкала подключена.

---

## **27\. Почему snapshot обязателен**

Snapshot нужен, чтобы:

1. старые попытки не ломались после редактирования теста;  
2. старые результаты не пересчитывались по новым вопросам;  
3. удалённые вопросы оставались в старых попытках;  
4. изменённые правильные ответы не меняли старые результаты;  
5. преподаватель мог безопасно обновлять тест.

---

## **28\. Answers после проверки**

После завершения попытки в `answers` нужно заполнить:

1. `is_correct`;  
2. `points_earned`;  
3. `max_points`;  
4. `question_snapshot_json`.

---

## **29\. Raw score**

Поле:

`attempts.raw_score`

Считается как сумма:

`sum(answers.points_earned)`

---

## **30\. Max raw score**

Поле:

`attempts.max_raw_score`

Считается как сумма:

`sum(answers.max_points)`

или берётся из snapshot, если он корректно зафиксирован.

---

## **31\. Percent**

Поле:

`attempts.percent`

Формула:

`percent = raw_score / max_raw_score * 100`

Округление:

1. можно хранить decimal;  
2. в интерфейсе показывать до 1 знака после запятой или целым числом.

Рекомендация для MVP:

показывать до 1 знака после запятой.

Пример:

`67.5%`

---

## **32\. Level**

Поле:

`attempts.level`

Рекомендуемая шкала уровней:

1. 0-39% \- низкий;  
2. 40-59% \- ниже среднего;  
3. 60-79% \- средний;  
4. 80-89% \- хороший;  
5. 90-100% \- высокий.

---

## **33\. Правило определения уровня**

Если `percent < 40`:

`низкий`

Если `percent >= 40` и `< 60`:

`ниже среднего`

Если `percent >= 60` и `< 80`:

`средний`

Если `percent >= 80` и `< 90`:

`хороший`

Если `percent >= 90`:

`высокий`

---

## **34\. Результат по темам**

Результат по темам обязателен в MVP.

Для каждой темы нужно посчитать:

1. `topic`;  
2. `score`;  
3. `max_score`;  
4. `percent`;  
5. `status`;  
6. список подтем с ошибками, если есть.

---

## **35\. Формула результата по теме**

Для каждой темы:

`topic_score = сумма points_earned по вопросам темы`

`topic_max_score = сумма max_points по вопросам темы`

`topic_percent = topic_score / topic_max_score * 100`

---

## **36\. Статусы тем**

Рекомендуемые статусы:

1. `weak`;  
2. `requires_review`;  
3. `normal`.

---

## **37\. Правила статусов тем**

Если `topic_percent < 60`:

`weak`

Если `topic_percent >= 60` и `< 80`:

`requires_review`

Если `topic_percent >= 80`:

`normal`

---

## **38\. Названия статусов в интерфейсе**

`weak`:

**Слабая тема**

`requires_review`:

**Требует повторения**

`normal`:

**Нормально**

---

    "wrong\_subtopics": \["Деепричастный оборот"\]  
  }

---

## **40\. Ошибки ученика**

В результате нужно показать список неправильных ответов.

Для каждой ошибки показывать:

1. номер вопроса;  
2. текст вопроса;  
3. тип вопроса;  
4. ответ ученика;  
5. правильный ответ;  
6. тема;  
7. подтема;  
8. баллы за вопрос;  
9. полученные баллы;  
10. объяснение, если есть.

---

## **41\. Правильные ответы**

В MVP правильные ответы показываются после завершения теста.

Показывать правильные ответы во время теста запрещено.

Для `single_choice` показать правильный вариант.

Для `multiple_choice` показать все правильные варианты.

Для `short_text` показать один или несколько допустимых правильных ответов.

---

## **42\. Explanation**

Объяснение необязательно.

Если `explanation` заполнено, его можно показать ученику после завершения теста.

Если `explanation` пустое, лучше не показывать пустой блок.

Не нужно писать:

**Объяснение не добавлено**

Если это визуально ухудшает результат.

---

## **43\. Рекомендации**

## **44\. Алгоритм рекомендаций**

1. Взять темы со статусом `weak`.  
2. Если таких тем мало или нет, взять темы со статусом `requires_review`.  
3. Внутри тем найти вопросы с ошибками.  
4. Собрать подтемы этих вопросов.  
5. Убрать дубли.  
6. Сформировать список рекомендаций.  
7. Ограничить количество рекомендаций до 3-5.

**Повторите тему “Пунктуация”: деепричастный оборот, сложноподчинённое предложение.**

Если подтем нет:

**Повторите тему “Пунктуация”.**

---

## **46\. Если слабых тем нет**

Если ошибок нет:

**Ошибок нет. Результат высокий. Для закрепления можно пройти следующий тест.**

## **48\. CE/CT scoring**

Режим ЦЭ/ЦТ должен поддерживать пересчёт первичного балла в тестовый балл 0-100 через таблицу соответствия.

---

## **49\. ScoringScheme**

Сущность `scoring_schemes` хранит описание шкалы.

Поля:

1. id;  
2. name;  
3. subject;  
4. exam\_type;  
5. year;  
6. max\_raw\_score;  
7. max\_scaled\_score;  
8. is\_active;  
9. created\_at;  
10. updated\_at.

---

## **50\. ScoringScale**

Сущность `scoring_scales` хранит соответствие:

1. первичный балл;  
2. тестовый балл.

Поля:

1. id;  
2. scoring\_scheme\_id;  
3. raw\_score;  
4. scaled\_score;  
5. created\_at;  
6. updated\_at.

---

## **51\. Пример шкалы**

Пример:

| raw\_score | scaled\_score |
| ----- | ----- |
| 0 | 0 |
| 1 | 3 |
| 2 | 6 |
| 3 | 9 |
| 40 | 100 |

Это пример структуры, а не финальная реальная шкала.

---

## **52\. Расчёт scaled\_score**

Если у попытки:

`raw_score = 27`

И в шкале есть запись:

`raw_score = 27`, `scaled_score = 72`

Тогда:

`attempt.scaled_score = 72`

---

## **53\. Правила CE/CT scoring**

1. Если тест в режиме `training`, scaled\_score не нужен.  
2. Если тест в режиме `ce_ct`, но шкала не подключена, можно показать только первичный балл.  
3. Если тест в режиме `ce_ct` и шкала подключена, нужно считать scaled\_score.  
4. Если `show_scaled_score = true`, но шкала не подключена, тест нельзя публиковать.  
5. Если `max_raw_score` теста не совпадает с `max_raw_score` шкалы, тест нельзя публиковать.  
6. Если raw\_score не найден в шкале, scaled\_score не показывать и записать ошибку в лог.

---

## **54\. Snapshot шкалы**

Если шкала подключена, при старте попытки нужно сохранить snapshot шкалы.

Нужно сохранить:

1. scoring\_scheme\_id;  
2. name;  
3. subject;  
4. exam\_type;  
5. year;  
6. max\_raw\_score;  
7. max\_scaled\_score;  
8. mapping raw\_score → scaled\_score.

---

## **55\. Зачем нужен snapshot шкалы**

Snapshot шкалы нужен, чтобы:

1. старые результаты не менялись после обновления шкалы;  
2. старые попытки оставались проверяемыми;  
3. изменения шкалы не ломали историю;  
4. можно было объяснить, по какой таблице считался результат.

---

## **56\. scoring\_scheme\_snapshot\_json**

Пример структуры:

{

  "name": "Русский язык ЦТ 2026",  
  "subject": "russian",  
  "exam\_type": "ct",  
  "year": 2026,

    {  
      "raw\_score": 1,  
      "scaled\_score": 3  
    }  
  \]  
}

## **57\. Проверка шкалы перед публикацией**

Если тест использует шкалу, перед публикацией проверить:

1. scoring\_scheme\_id выбран;  
2. шкала active;  
3. в шкале есть raw\_score \= 0;  
4. в шкале есть raw\_score \= max\_raw\_score;  
5. нет дублей raw\_score;  
6. scaled\_score находится в диапазоне 0-100;  
7. max\_raw\_score теста совпадает с max\_raw\_score шкалы.

---

## **58\. Импорт шкалы**

Шкала импортируется отдельным файлом.

Колонки:

1. `raw_score`;  
2. `scaled_score`.

Ошибки импорта шкалы:

1. нет обязательной колонки;  
2. raw\_score не число;  
3. scaled\_score не число;  
4. raw\_score дублируется;  
5. scaled\_score вне диапазона;  
6. нет raw\_score \= 0;  
7. нет raw\_score \= max\_raw\_score.

## **63\. Attempt complete API**

Endpoint:

`POST /api/attempts/:attempt_id/complete`

При вызове:

1. проверить, что attempt.status \= started;  
2. заблокировать изменение ответов;  
3. проверить все ответы;  
4. заполнить answers.is\_correct;  
5. заполнить answers.points\_earned;  
6. посчитать raw\_score;  
7. посчитать max\_raw\_score;  
8. посчитать percent;  
9. определить level;  
10. посчитать topic\_results\_json;  
11. сформировать recommendations\_json;  
12. посчитать scaled\_score, если нужно;  
13. обновить attempt;  
14. вернуть ссылку на результат.

---

## **64\. Attempt expire API**

Endpoint:

`POST /api/attempts/:attempt_id/expire`

При вызове:

1. проверить, что время действительно вышло;  
2. если время не вышло, вернуть ошибку;  
3. если время вышло, выполнить ту же scoring-логику, что и при complete;  
4. статус попытки поставить `expired`.

---

## **65\. Идемпотентность завершения**

Если complete или expire вызваны повторно:

1. не пересчитывать результат заново без необходимости;  
2. не менять already completed результат;  
3. вернуть текущий result\_url;  
4. не создавать дубли логов.

---

## **66\. Edge cases**

### **66.1. Все ответы правильные**

Показать:

1. максимальный балл;  
2. высокий уровень;  
3. сообщение: **Ошибок нет. Результат высокий.**

Список ошибок пустой.

---

### **66.2. Все ответы неправильные**

Показать:

1. 0 баллов;  
2. низкий уровень;  
3. все темы со статусом weak;  
4. все вопросы в списке ошибок.

---

### **66.3. Часть ответов пустая**

Пустые ответы считаются ошибками.

В результате показывать как:

**Ответ не дан**

---

### **66.4. Нет подтем**

Рекомендации строятся по темам.

---

### **66.5. Нет explanation**

Пустой блок объяснения не показывать.

---

### **66.6. max\_raw\_score \= 0**

Такой тест нельзя публиковать.

Если ошибка всё же возникла при расчёте:

1. не делить на 0;  
2. вернуть техническую ошибку;  
3. записать event\_log.

---

### **66.7. raw\_score не найден в шкале**

Если включён CE/CT scoring и raw\_score отсутствует в шкале:

1. scaled\_score не показывать;  
2. raw\_score показать;  
3. записать ошибку в event\_logs;  
4. админу показать проблему в деталях попытки.

---

### **66.8. Шкала изменилась после попытки**

Старый результат не пересчитывать.

Использовать `scoring_scheme_snapshot_json`.

---

### **66.9. Вопрос удалён после попытки**

Старый результат не меняется.

Использовать `question_snapshot_json`.

---

### **66.10. Правильный ответ изменён после попытки**

Старый результат не меняется.

Использовать snapshot.

---

## **67\. Event logs**

Scoring Engine должен создавать события:

1. `attempt_completed`;  
2. `attempt_expired`;  
3. `result_calculated`;  
4. `scoring_error`;  
5. `scaled_score_missing`;  
6. `scoring_scheme_snapshot_created`.

---

## **68\. Транзакция расчёта**

Завершение попытки и расчёт результата должны выполняться в transaction.

В transaction:

1. заблокировать attempt;  
2. проверить статус;  
3. проверить ответы;  
4. обновить answers;  
5. обновить attempt;  
6. записать event\_log.

Если ошибка:

1. откатить transaction;  
2. не оставлять attempt в частично завершённом состоянии;  
3. записать ошибку.

---

## **69\. Безопасность**

Требования:

1. ученик не может запросить правильные ответы до завершения;  
2. ученик не может завершить чужую попытку;  
3. ученик не может посмотреть чужой результат;  
4. frontend не передаёт `is_correct`;  
5. frontend не передаёт `points_earned`;  
6. frontend не передаёт `raw_score`;  
7. backend сам считает все результаты;  
8. admin может смотреть все результаты;  
9. student может смотреть только свои результаты.

---

## **70\. Admin settings для результата**

В админке у теста должны быть настройки:

1. показывать процент;  
2. показывать правильные ответы;  
3. показывать результат по темам;  
4. показывать рекомендации;  
5. показывать тестовый балл 0-100;  
6. выбрать шкалу оценивания.

Для MVP можно включить большинство настроек по умолчанию:

1. show\_percent \= true;  
2. show\_correct\_answers \= true;  
3. show\_topic\_result \= true;  
4. show\_recommendations \= true;  
5. show\_scaled\_score \= false, если шкала не подключена.

## **71\. Acceptance Criteria**

Scoring Engine считается готовым, если:

1. backend проверяет `single_choice`;  
2. backend проверяет `multiple_choice`;  
3. backend проверяет `short_text`;  
4. `multiple_choice` засчитывается только при полном совпадении;  
5. `short_text` проверяется по точному совпадению после нормализации;  
6. пустые ответы считаются неправильными;  
7. за правильный ответ начисляется полный балл;  
8. за неправильный ответ начисляется 0;  
9. частичные баллы не начисляются;  
10. raw\_score считается корректно;  
11. max\_raw\_score считается корректно;  
12. percent считается корректно;  
13. level определяется корректно;  
14. topic\_results считаются корректно;  
15. рекомендации формируются по слабым темам;  
16. правильные ответы не отдаются до завершения;  
17. после завершения правильные ответы доступны в результате;  
18. объяснения показываются только если заполнены;  
19. результат считается только на backend;  
20. результат сохраняется в attempt;  
21. answers получают is\_correct и points\_earned;  
22. completed attempt нельзя изменить;  
23. expired attempt считается по сохранённым ответам;  
24. CE/CT шкала может быть подключена к тесту;  
25. scaled\_score считается по raw\_score, если шкала есть;  
26. если raw\_score отсутствует в шкале, ошибка логируется;  
27. snapshot теста используется при расчёте;  
28. snapshot шкалы используется при расчёте, если шкала подключена;  
29. старые результаты не меняются после редактирования теста;  
30. ученик не может смотреть чужой результат;  
31. админ может смотреть детальный результат попытки.

## **75\. Итог**

Scoring Engine v2 должен обеспечить надёжную автоматическую проверку теста в первой версии продукта.

Ключевые требования:

1. результат считается только на backend;  
2. используется snapshot теста;  
3. поддерживаются `single_choice`, `multiple_choice`, `short_text`;  
4. в MVP нет частичных баллов;  
5. ученик видит ошибки и правильные ответы только после завершения;  
6. результат по темам обязателен;  
7. рекомендации формируются без AI;  
8. CE/CT scoring должен быть заложен архитектурно;  
9. старые результаты не должны ломаться после изменения теста.
