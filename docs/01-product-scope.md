# Product Scope

## Главная цель

MVP должен доказать одну коммерческую цепочку:

преподаватель создает тест -> публикует его -> ученик получает доступ через оплату, ручную выдачу или код -> проходит тест -> видит результат -> преподаватель видит оплату, доступ и результат.

## Роли

- Администратор / преподаватель: работает в админке, создает тесты, вопросы, импортирует XLSX/CSV, публикует тесты, управляет оплатами, доступами, кодами и результатами.
- Ученик: работает в публичной части, вводит email, получает доступ, проходит тест и видит результат.
- Родитель: отдельной роли нет. Если родитель платит, доступ привязывается к email, указанному при покупке.

## В MVP входит

- Один предмет: `russian`.
- Два режима теста: `training`, `ce_ct`.
- Покупка одного конкретного теста.
- 1 покупка = 1 попытка, но `attempts_limit` хранится как настройка.
- Срок доступа по умолчанию: 7 дней.
- Ученик без пароля, идентификация по нормализованному email.
- Три типа вопросов: `single_choice`, `multiple_choice`, `short_text`.
- Обязательная тема вопроса.
- Необязательная подтема и explanation.
- Импорт XLSX/CSV.
- Оплата, ручная выдача доступа и одноразовые коды.
- Snapshot попытки.
- Backend-only scoring.
- Результаты по темам.
- Шкала ЦЭ/ЦТ 0-100 в MVP.

## В MVP не входит

- AI любого вида.
- Ученический аккаунт с паролем.
- История тестов ученика.
- Подписки, пакеты, курсы, абонементы.
- Банк вопросов.
- Частичные баллы.
- Сложные типы заданий.
- PDF, рейтинги, группы, чат, CRM.
- Автоматические возвраты.

## Критерий готовности

MVP готов, когда выполнены acceptance criteria из Final MVP Spec v2, раздел 62.
